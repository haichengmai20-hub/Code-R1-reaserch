# 训练归因 Bad Case 库（环境误判 vs 策略问题的第一道排查工具）

**定位：** 训练（真跑或推演）之后分析 reward 异常时，**先查本表排除环境问题，再怀疑训练策略**。每条案例都是已查明根因、有实测证据的判分异常——命中即环境问题（修环境/换口径/剔除题），未命中才往策略层查。

**用法（三阶段）：**

| 阶段 | 动作 | 工具 |
|---|---|---|
| 训练前 | **预检扫雷**：参考解全量判分，把会误判的题先标出/剔除 | `verify_gt_contract.py`（2090 题两契约对照）；`verify_verifier_metrics.py`（三路径量化审计：作弊解拦截/错解误过/变异杀死率）；`coder1_plus_selection.py`（去重/筛题） |
| 训练中 | 曲线/日志异常 → 按[症状速查表](#symptom-index)反查 | 本表 |
| 训练后 | bad case 抽样 → 查本表 → 命中=环境（排除）→ 未命中 → 策略层（学习信号、探索、超参） | 本表 + [04 的故障归因](04_真实训练与独立评测.md#attribution-4) |

**归因铁律：一条 reward 异常，先用参考解复现——参考解也拿同样的分，就是环境实锤**（模型无关）；参考解能拿对分、模型拿不到，才可能是模型行为。

**口径字段说明：** `legacy` = 原版 coder1 判分 + 原版数据（推演产物钉的口径）；`plus` = coder1_plus + 补强数据；`both` = 都会出现。

## 一、数据 / GT 层

### BC-01 树和链表题：正确解恒 0.1（prelude 缺失）★本库原型案例

- **症状签名**：121 道树/链表题的 reward 恒 0.1 或 −1.1，无论训练多少步；这些题的组内全 0.1 → advantage 全 0 → 曲线上是"这片题永远没信号"。rollout 里模型明明写了正确算法。
- **根因**：GT 拼装不含原始 `prompt` 前缀，而测试调用的 `tree_node`/`is_same_tree`/`list_node`/`is_same_list` 只在前缀里定义 → 正确解也 `NameError`。
- **验证**：参考解跑该题同样 0.1（环境实锤）；对照实跑 `create-binary-tree-from-descriptions`：legacy 拼法失败、带前缀通过（2026-10-13 实测）。
- **口径**：`legacy`。plus 口径 GT 带 `prelude` 字段，121 题从 0.1 全部变 1.1。
- **状态**：已修（补强项 1）。训练若跑 legacy 数据（如推演复现），这些题应预检剔除。

### BC-02 测试=题面样例太弱：错解蒙到 1.1（假阳性）

- **症状签名**：某题 reward 高但独立评测（held-out）不涨——训练分与真实能力脱节。`wrong_empty` 型错解（允许空子数组）在 LeetCode 53 的 3 条正数 seed 上拿满分。
- **根因**：1890 题的 test 全是题面样例（中位 2 条、93% ≤3 条），覆盖不了边界；样例答案全正数时"空子数组"歧义不可判。
- **验证**：变异审计——2014 题 17316 个变异体，样例测试只杀 81%；LeetCode 53 杀 9/9 仍放过 wrong_empty。三路径量化审计（2026-11-01，`verify_verifier_metrics.py`，7 题 × 正确解/错解/6 变异/作弊解 × original/legacy/protected）：**错解误过率 25%，三条路径相同**——弱测试是数据属性，换判分协议救不了；变异杀死率 93.1%。
- **口径**：`both`（测试强度是数据属性，判分器只忠实执行）。
- **状态**：部分修（补强项 2 审计 + 补强项 3 oracle 补测；oracle 覆盖到的题已补，全量补测待做）。**训练解读红线：训练 reward 上涨 ≠ 能力提升，必须独立评测。**

### BC-03 同题同答时过时不过：判分不稳定

- **症状签名**：同一 checkpoint 的验证分数抖动；rollout 里同题型 reward 无规律起伏；无任何代码改动曲线自己漂。
- **根因**：`word-ladder-ii` 参考解输出顺序随哈希种子变化，测试却按列表顺序比较——6 个种子只过 3 个。
- **验证**：同程序多 seed 重跑，判分结论翻转。
- **口径**：`legacy`（plus 的 `compare=unordered_outer` 已修；68 题题面写 "in any order" 但顺序比较的同类问题一并修）。
- **状态**：已修（补强项 4）。

### BC-04 缺第三方库的题：全组恒 0.1、题白占 batch

- **症状签名**：特定题 reward 从第一步到最后一步恒 0.1（格式对、执行失败），参考解也一样；这些题永远零梯度但占着 batch 位。
- **根因**：14 题测试需要 `sortedcontainers`（13 题）/`numpy`（1 题），沙箱 Python 环境没装。
- **验证**：参考解跑该题 0.1（环境实锤）。
- **口径**：`both`。
- **状态**：未修（属环境依赖，非判分逻辑）——**护栏：训练前预检剔除**（补强项 7 的 keep 清单机制可用）。

### BC-05 TACO 数据的两处血缘缺陷

- **症状签名**：TACO 题的 reference 与判分结果对不上；stdio 题测试条数莫名 ≤8 条。
- **根因**：验证用 `solutions[-1]`、保存的 reference 是 `solutions[0]`（不是同一份程序）；`minimize_stdio` 只留最小 8 条、跳过 >4KB stdin，条数不等时 `zip` 静默截断。
- **口径**：`both`（数据侧属性）。
- **状态**：未修（现版主线已去 TACO；若混入需预检）。

### BC-06 数据路径不匹配：训练根本起不来

- **症状签名**：`main_grpo.sh` 找不到数据文件，训练第一步就崩。
- **根因**：预处理输出目录名 `code-r1-{N}k-leetcode2k-taco/`，脚本读 `data/code-r1-12k/`。
- **口径**：`both`。**状态**：未修（配置事实，用前对齐路径）。

### BC-19 评测集与训练集同题：验证分数虚高

- **症状签名**：验证分数与训练分数同步虚高，held-out 才露出真实水平。
- **根因**：v1 test 与 v2 训练集有 61 对同题号、3 对措辞重叠——题目见过，等于考卷混进课本。
- **验证**：`coder1_plus_selection.py` 的去重对照输出。
- **口径**：`both`（数据划分属性）。**状态**：已修（补强项 7 去重）；自建评测集必查。

### BC-20 信息缺失型：题面没给约束，模型蒙不对语义

- **症状签名**：某类题模型长期学不会，但看 rollout 发现两种合理解读各拿不同的分——不是模型不会，是**题目没说清**（环境没给够信息）。典型：空子数组歧义在缺 `-10^4 ≤ x` 约束时无法从题面判定。
- **根因**：prompt 不含 Constraints，语义边界悬空；模型按另一解读写对代码仍被扣分。
- **验证**：给 prompt 补上约束后同模型重答，分数分化消失（对照 `--append_constraints` 前后）。
- **口径**：不开 `--append_constraints` 时。**状态**：已修（1846/1890 题自动补）。**与 BC-02 的区别：BC-02 是测试弱（判不出错），本条是信息缺（说不清对）——一堵一疏，都是环境问题，都不是模型问题。**

## 二、判分器层

### BC-07 提前退出骗满分：模型学会的不是解题（假阳性）★高频陷阱

- **症状签名**：reward 上涨很快但代码质量下降——rollout 里出现 `sys.exit(0)` 型回答；独立评测崩。
- **根因**：判分把"候选+断言"拼成一个程序跑，只看退出码 0；候选第二行 `sys.exit(0)`，断言一条没执行也拿 1.1。
- **验证**：固定候选 `early_exit` 实测拿 1.1、独立审计完成的测试数为 0（`report.json`）。
- **口径**：`legacy`（plus 的受保护协议：期望答案不进候选进程、逐条上报、缺结果判失败）。量化审计确认这是**机制性差异**：作弊解在 original/legacy 均误过、protected 全拦——正确解 7/7 三路径零误拒。
- **状态**：已修（补强项 4）。**训练解读红线：reward 虚高先查骗分模式再谈能力。**

### BC-08 格式边际倒挂：整洁的错答压过不整洁的对答

- **症状签名**：模型趋向"格式完美但答案平庸"；`<think>/<answer>` 合格率飙升而正确率不动。
- **根因**：三档 −1.1/0.1/1.1 里格式边际 1.2 > 正确边际 1.0，组内标准化放大为排序错位；对但格式错的回答在格式门直接 −1.1，代码根本不执行。
- **验证**：`[1.1, 0.9, 0.1, −0.1]` 与排序断言（min(对)=0.9 > max(错)=0.1）单元测试通过。
- **口径**：`legacy`（plus 字典序四档 + 无标签退回最后代码块照样执行）。
- **状态**：已修（补强项 9）。

### BC-09 两套代码提取规则：同回答不同判分

- **症状签名**：回答里先有草稿代码块、再有最终代码块时，跨评测器对比分数不一致（训练分 vs 原生评测分）。
- **根因**：coder1 取**最后一个** `<answer>` 里**所有**代码块拼接；原生 `leetcote` 取**最长**块。草稿含异常时一个 0.1 一个通过。
- **口径**：`both`（两套提取器并存于仓库）。
- **状态**：文档化（行为差异，非 bug）；对比两套分数时必须先统一提取口径。

### BC-22 answer 内多块拼接：后块覆盖前块，顺序翻转分数

- **症状签名**：同一段正确代码，回答里草稿块与正文块的先后顺序不同，分数在 1.1 与 0.1 之间翻转（2026-11-08 实测：草稿前/正文后=1.1；正文前/草稿后=0.1）。
- **根因**：提取把 answer 内的全部围栏块 ```'
'.join``` 拼接成一个程序执行；Python 的同名类后定义覆盖前定义——排在最后的块才是实际生效的代码。
- **验证**：`extract_walkthrough.py` 的 C 案例两序对照（真实判分实测）。
- **口径**：`both`（提取规则上游与本仓相同）。**状态**：已知行为（文档化）。训练解读：模型在 answer 内并列多块时，实际被判分的是**最后一块**；归因时先看提取拼接，再谈代码对错。护栏是教学性的——草稿放 answer 外会被缩围天然排除。

### BC-23 爬虫解析器三类坑（上游重建时）

- **症状签名**：从官网重建数据时，entry_point 变成 `__init__`、多参数题 test 语法靠碰巧正确、链表/树题参考解跑 test 永远失败。
- **根因**：① starter 注释块里的 `# def __init__` 被正则匹配；② 多参数输入 `a = ..., b = ...` 被贪婪正则整体吞进第一个值；③ ListNode/TreeNode 返回值直接用 `==` 比较（对象身份而非内容）。
- **验证**：crawler.py v1 在 10 题上实测暴露（entry=Solution().__init__）；v2 修复后 10/10，行为层 3/3 PASS。
- **口径**：上游重建（非训练判分）。**状态**：已修（crawler v2）。训练无关，但重建数据集/写判分器时同类坑会重现。

### BC-24 模型覆盖环境辅助类：正确解被判错（假阴性）

- **症状签名**：链表/树题的正确解稳定拿 0.1，判分日志报 `AttributeError: 'ListNode' object has no attribute 'val'`；rollout 里模型解题逻辑正确，只是顺带自己定义了 ListNode。
- **根因**：模型回答与 prelude 在同一命名空间执行，模型写的 `class ListNode`（成员名写错或缺字段）覆盖了环境定义；prelude 的 `list_node`/`is_same_list` 依赖环境版 ListNode，于是正确解被判失败。**判分器没算错，是命名空间隔离缺失**——环境侧设计的坑。
- **验证**：2026-11-08 实测——构造「错误 ListNode + 正确解」，修复前退出码 1、修复后 1.1 passed（`protocol.py` 新增 reserved 恢复）。
- **口径**：`plus` 与 `legacy` 同源（都拼同一命名空间）。**状态**：已修——exec 前备份 `ListNode/TreeNode/list_node/tree_node/is_same_list/is_same_tree`，exec 后恢复；模型只保留自己的 `Solution`。
- **训练解读**：这类错会**系统性压低某类题的 reward**（链表/树题），曲线看起来像"模型不会树题"——按归因铁律先查环境（`bad_case` 本表），再怀疑策略。

## 三、奖励管理器层

### BC-10 判题故障回填 0.0：错误回答反被奖励 ★曲线尖刺的元凶

- **症状签名**：reward 曲线周期性尖刺/骤降；某步大量样本 0.0；同组错误回答的 advantage 变正。
- **根因**：管理器单样本超时（600s）或异常时回填 0.0——0 不是中性值，它进组内均值：`[0.1, 0.1, 0.1, 0.0]` → advantage `[+0.5, +0.5, +0.5, −1.5]`，三条错误回答被组内标准化放大成"比故障好"的正信号。
- **验证**：CPU 受控演示（`run_demo.py advantage` 的 infra 回填行）；your-01 推演第五环的沙箱超时作废事故即此模式。
- **口径（2026-11-09 起，D15）**：现版 `prime_plus` 先重试，仍失败**单条掩码**——故障样本分数＝组内有效均值，advantage 恰为 0，其余 rollout 照常（全故障组作废）；`CODER1_PLUS_INFRA_POLICY` 可切回 `neutralize_group`/`legacy_zero`。
- **状态**：已修（补强项 6；2026-11-09 由整组作废升级为单条掩码）。

### BC-11 用错管理器：全批 −1.1

- **症状签名**：从第一步起几乎所有回答 −1.1，格式学习完全不发生。
- **根因**：`naive.py` 管理器解码 prompt+response 整段，coder1 的"`<think>` 开头"检查永远失败（推断，未跑）。
- **口径**：配置错误（`reward_manager=naive` 时）。**状态**：配置事实——用 `prime`/`prime_plus`。

## 五、策略配置层（不误判 reward，但影响曲线解读）

> 这层不是"环境误判"，是**配置运行态事实**——归因时不知道它们，会把正常现象当异常。

### BC-14 grad_norm 偏小 16 倍：mini-batch 语义错配

- **症状签名**：`actor/grad_norm` 数值异常小；怀疑"梯度消失"。
- **根因**：脚本按"回答数"算 256，verl 按"题数"×16 → 每 GPU mini=512 但只有 32 条回答 → 梯度缩到 micro 均值的 1/16；`grad_clip=1.0` 实际放宽 16 倍。AdamW 抵消常数缩放，训练仍收敛。
- **口径**：`main_grpo.sh` 原配方（课程小配置 Q4/G4 恰好不触发）。**状态**：源码推断（未实跑验证）。

### BC-15 clip 形同虚设：ratio 恒 1

- **症状签名**：`actor/pg_clipfrac ≈ 0`，怀疑"clip 参数没生效"。
- **根因**：`ppo_epochs=1` 且单 mini-batch 时，update 用的权重就是算 `old_log_probs` 的权重 → ratio≈1。clip 机制本身没坏，是配置下不触发。
- **口径**：`main_grpo.sh` 原配方。**状态**：源码推断。

### BC-16 首步 lr=0、实际少一步更新

- **症状签名**：第一步 `actor/lr` 显示 0；总步数差 1。
- **根因**：`lr_warmup_steps_ratio=0` 的边界行为；循环计数 `>=` 即停。
- **口径**：v0.4.1 前的 verl。**状态**：源码推断（v0.4.1 已改）。

### BC-17 验证分数是 raw reward 均值，不是通过率

- **症状签名**：`val/test_score/code` 看起来很低或为负，怀疑"模型退步"。
- **根因**：它是每条 reward（−1.1/0.1/1.1 混合）求和后的均值——LeetCode/TACO 合并统计，格式失败拖垮均值。
- **口径**：`both`。**状态**：设计如此；要通过率需自算 pass@k（`leetcote` 的 `estimate_pass_at_k` 可用）。

### BC-18 起不来/分错支：vLLM 版本三坑

- **症状签名**：单卡+0.7.3 首次生成就 `NotImplementedError`；`0.6.3.post1` 被字符串比较分进 spmd 分支报不支持；没装 vLLM 报 TypeError。
- **口径**：单卡用 0.6.3（精确版本）。**状态**：源码推断+实测（Hydra 中文路径要加单引号同属此类）。

### BC-21 执行后端三坑：stdin 崩、重试死循环、结果旁写

- **症状签名**：docker 后端跑大 stdin 题直接崩（引用未定义 `stdin_path`）；ces/kira 后端在服务不在时 `while True` 每 3 秒重试、训练整卡卡死；原生 eval 工具在输入文件旁写结果文件（污染数据目录）。
- **口径**：`CODER1_EXEC=docker/ces/kira` 或用原生评测时。**状态**：配置事实——训练固定 firejail/plus 沙箱；原生工具输出目录要隔离。

## 症状速查表（训练时按观察反查）

| 观察到的症状 | 先查 | 条目 |
|---|---|---|
| 某片题 reward 恒 0.1，参考解也 0.1 | 数据层 | BC-01（树/链表）、BC-04（缺库） |

1. 新发现判分异常：先复现（参考解优先），查明根因与口径，按五要素登记，能修的修（直接落现版源码，按 D11），修完更新状态；
