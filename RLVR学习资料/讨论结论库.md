```text

  ①这是合法输入吗？ ②程序交出了可判定的输出吗？ ③输出等于期望吗？
```

## 2026-11-09 · 600 秒管理器超时的来源与可标定性 — D15 配套论证

**核心输出：**

```text
最坏合法墙钟 ≈ (批大小 ÷ 线程数) × 沙箱限时 = 256 ÷ cpu_count × 30s
  32 核 ≈ 240s（600 够）；8 核 = 960s > 600（全组顶满沙箱时会误伤排队样本）
smoke test 标定法（与 perf 同构）：全死循环批次实测最慢单样本墙钟 × 安全系数
  → manager_timeout_s；现版有重试，按重试后口径标定。低核节点进「实跑前必查」。
占位值对拍（GRPO 同款公式，[0.1,0.1,0.1,占位]）：
  0.0 → [+0.5,+0.5,+0.5,−1.5]  错答被奖励（BC-10）
  0.2 → [−0.5,−0.5,−0.5,+1.5]  占位样本拿全组最强正信号（std=0.05，绝对差距活不过标准化）

  单条掩码 → 故障样本恰 0        「不知道」的正确表达（D15 落地）
本质：占位值不是分数是认知状态；任何具体数值都在替未知质量伪造主张。
```

## 2026-11-10 · 三指标归属与拦截率的拆轴归因 — D13 §2 配套

**核心输出：**

```text
必需语义项/边界覆盖率 → 纯数据面：考题全不全（对清单打勾，verifier 不参与）
测试区分力（错解池）  → 数据面：考题狠不狠（对每个已知错解存在能区分它的测试）
判分保真度            → verifier 面：阅卷准不准（能区分的必拒 + 正确解零误杀）

快捷视角：逐题拦截差异几乎全来自数据（verifier 是通用机器、题目特异性全在数据行）；
          verifier 的缺口表现为跨题系统性模式（bad case 库按层登记的就是这些）。
```

## 2026-11-10 · oracle 的定义与作用位置 — D16 配套

**核心输出：**

```text
oracle = 独立于被验证对象的答案求解/核对器。三关键词：独立（与被审对象不同源，
否则互证一起错）、求解或核对答案（算 expected / 对答案）、它自己不判分。
作用位置：只在离线数据侧（造样例算 expected、审参考解、扩容终审）；
不进在线 verifier——意志以 expected 字面量冻结进 GT（assert 里的 -2 就是它定的），
在线判分只比较候选输出与冻结值，从不跑 oracle。
为什么不在线：成本（傻解法跑不动大输入、每步 256 次判分现算爆炸）＋
稳定性（冻结值可复现、判分标准不漂移，oracle 自身故障被挡在判分路径外）。
口诀：oracle 是出卷时的标答制定者，verifier 是阅卷时拿印好答题卡的比对者。
```

**状态：** 压缩版已入 01 次图③旁；本条为完整版。

## 2026-11-10 · 错解池三源辨析：变异体 / 语义错解 / 模型真实输出 — D18① 配套

**核心输出（三源各补一块错误分布，缺一块就是盲区）：**

```text
变异体     ＝实现级失误：题意理解对、代码写错（边界差一、比较符错）。
            操作发生在代码上（单点改动），得到的只是「疑似错解」——要找到
            合法输入使其输出 ≠ oracle（可信反例）才算确认；找不到反例的
            标「未定」，不算错解（可能是等价变异）。「每个都带可信反例」
            就是这道入池门槛：变异性 ≠ 确认性。
语义错解   ＝题意级偏差：代码完美实现「另一种题意理解」——wrong_empty 对
            「允许空子数组」的题是满分实现、wrong_sum 理解成返回总和。
            变异造不出它：变异只在参考解的代码结构里小改，参考解里根本
            没有那种理解的代码可改。
模型真实输出＝分布真样本：训练/采样时模型的真实回答，尤其是恰好骗过现有
            测试的错答案（特判样例的解、reward hacking 雏形）——只有
            rollout 能产出，直指测试缺口。三源里只有这一类是模型产生的。
只用变异体为什么不够：池子要近似模型真实错误分布——模型既犯实现错、也犯
题意误解、还会发明特判；只放变异体，100% 检出率只证明「能抓实现级失误」，
对题意级错误是盲的——假安全感（D18① 错误分布匹配的延伸）。
```

**状态：** 已入 01 主图扩容带判据②（压缩版）；本条为完整版。

## 2026-11-10 · 语义错解的造法、escaped 错解的挑法与双盲漏检的有界化 — D13 §6 配套

**核心输出：**

```text
语义错解四造法（全部过 oracle 反例门槛；反例＝区分两种题意理解的输入）：
  ①歧义清单系统枚举（主力）：空输入？区间开闭？任意解/最优解？多解顺序？tie-break？
    取模？——逐项写「按另一种理解实现」的解；wrong_empty/wrong_sum 出自此清单
  ②LLM 生成误读（读题面枚举合理误读，产出是候选仍要反例确认）
  ③人写（试点题与高风险题）  ④真实错误回填（越训越准）

escaped 错解（错但拿满分）三挑法——关键是重判必须用没参与过训练判分的新输入：
  ①新输入重赛（核心）：满分回答分层抽样，用刻意留出的审计输入集（D13 §6）
    再考——新卷上露馅即实锤，暴露输入进回归测试
  ②oracle 重判：抽中回答在新生成输入上对拍 oracle（离线，证据规模不限）
  ③统计侧写找可疑点：突然全组满分而历史低通过率；reward 涨 dev 不涨；
    同题多条满分解在新输入上行为不一致

双盲漏检（verifier 没拦 + 审计没看）——结构性风险，目标是有界且递减而非零：
  ①多层漏斗：训练判分→审计新卷→held-out 评测→效果归因；层层独立，漏过需相乘
  ②污染有缓冲：组内区分度筛题（0<c/n<1）保证对错混合——错解只骗过测试的那组
    拿正 advantage，污染有限且随测试增强递减
  ③闭环回报：每个被发现的 escaped 错解的暴露输入进回归测试，同类漏检单调下降
  ④统计上界：300 个满分错解零漏判 ⇒ 漏判率 < 1%（95%）——把「不知道有没有」
    变成「知道有多少」
根除不可能（有限证据的认识论限制）；逼近零靠外循环——新测试持续注入、
人工/更强模型复核、red team 对抗（工业 data flywheel 同构）。
```

**精确化（2026-11-10，用户追问「GT 不是从没给模型看过吗」）：**「泄题」比喻在信息层不成立——
GT 内容模型确实从没见过（判分隔离已防住**信息泄露**）。真正泄的是**目标**：测试集定义 reward、
reward 是优化目标，「过/不过」一个 bit 就足以塑造策略——与正确解在现有测试下同分的错解拿到
同样的正 advantage、被一起强化（选择压强≈背题，但无信息传递）。held-out 输入的理由精确表述：
参与过判分的输入测「对代理指标的拟合度」，held-out 输入测「真·正确性」——即 train/test split
的 Goodhart 版论证。两种泄露对照：信息泄露→判分隔离可防；目标泄露→只能靠 held-out 缓解。

**状态：** 未入正文（候选：测试扩容方案 §6 旁 / 04 归因节；D13 §2「获奖励程序的复审错误率」与 §6 已覆盖机制骨架，本条补方法与边界论述）。

## 2026-11-10 · 冒烟门控晋升协议：审计闭环跑在 smoke 里，达标才上正式训练 — D19

**核心输出：**

```text
为什么放 smoke：真实 rollout 才产生真实错误分布（模型真实输出这一源只有真训练能给），
smoke 是最便宜的「真实环境」；把测试盲区在花大钱之前压掉。

预注册判据（开跑前写死）：
  escaped 率 = 满分回答在 held-out 输入上的失败比例   （要 ≤ X%）
  误杀率     = 正确解被拒比例                         （必须 = 0）
  样本量绑定置信度（rule of three：0 漏判 / N 样本 → 95% 上界 ≈ 3/N）：
    N=20 → ≤14%   N=60 → ≤5%   N=300 → ≤1%
  冒烟用粗阈值（如 N=60、≤5%、误杀 0）；<1% 的硬上界只能靠正式训练期审计补。

循环：smoke 跑 → 审计满分卷（held-out 重赛 / oracle 对拍）→ 五条反馈路
（回归 / 定向扩容 / 清单修正 / 训练决策 / 不动）→ 重跑，直到达标。
晋升：冻结 test_version 作正式 GT；审计不停止（正式训练期与之后继续抽检——
模型变强会出新错法，smoke 达标只是准入证据，不是终身保证）。
预算内不达标：记缺口带风险标记进入或缩小规模；不无限循环、不假装达标。

三个容易糊掉的点：
  ①「失败率」必须定义成 escaped 率（不是 reward、不是测试失败率），且与样本量一起写死；
  ②承重前提是测试可再生（D16/D17），否则 held-out 用一次就废；
  ③冒烟模型 ≠ 正式模型，阈值可迁移的是「准入判断」，不是「性能承诺」。
```

```text
样本量（精确二项 95% 上界）：
  N=60,0 漏 → 4.9% 可停   N=100,0 → 3.0%   N=100,1 → 4.7%
  N=100,2 → 6.2% 不通过   N=100,4 → 8.9%（点估计 4% 也不算过）

  测试质量 = 策略无关 → 强模型离线对抗审计（产量高、错误形态接近聪明解；

  误杀率 → oracle/已知正确解，不需模型
```

## 2026-11-13 · 判分两轮的离线/在线成本与扩容定案 — D21/D17 修订/D13 补参

**定案关联：** D21（超约束输入赋分）、D17 修订（语义边界获取方式）、D13 补参（扩容参数）。正文落点：02 新增[判分两轮](02_Verifier与任务池验收.md#two-rounds-2)节、01 新增 [expected 分层](01_数据理解与GT构建.md#expected-layering-1)段。

### A. 两轮在时间轴上的位置

```text
【离线·数据构造，一次性，训练前】
  ├─ 测试用例集：题面样例 + 数值边界 + 随机（过 validate 筛选）
  ├─ expected：小域 oracle 直出 / 大域参考解（信任链）
  └─ perf 标定：参考解在种子大输入上实测墙钟 ×3（系数）→ time_limit_ms
     + 大输入的 expected（参考解算）+ 种子
     ——全部写进数据行 extra_info.perf，到此离线结束

【在线·verifier 判分，每个 rollout、每一步都跑】
  候选回答进来后顺序：
  门③ 提取代码
    ↓
  ┌─ correctness 轮（正确性轮）：候选 + 全部用例 → 拼程序/受保护协议执行
  │    钟 = 沙箱整体钟（firejail 30s / 管理器 600s 兜底）
  │    只判对错：过 → 可能继续；挂 → 0.1
  └─ perf 轮（性能轮，条件触发：上轮过了 且 数据行带标定）：
       种子确定性重建那条大输入 → 用离线标好的 time_limit_ms 当 timeout 跑一次
       超时 → 0.9（对但慢）；大输入答错 → 0.1
```

「轮」是判分内部的两个阶段，不是「离线一轮、在线一轮」。离线产出的只有三样：用例、expected、每题一个 time_limit_ms——**连钟都是离线算好带进来的**：判分时零标定，同题各步不漂移。

### B. 成本按离线/在线分开记

| 成本 | 何时发生 | 量级 |
|---|---|---|
| 用例生成+validate 筛选 | 离线，一次性 | 每题按 D13 分级预算（候选池 40-80/200/1000，入 GT 10~30 条） |
| expected 计算 | 离线，一次性 | 小域 oracle 跑得动；大域参考解每题一条 |
| time_limit 标定 | 离线，一次性 | **每题 1 次参考解执行**（量一次墙钟）。「每用例一个钟」= 条数×1 次测量/题 × 1890 题 ≈ 5.7 万次——买到的判别力和 perf 轮重复，所以不做 |
| correctness 轮执行 | 在线，每 rollout 每步 | 条数 × 16 rollouts × 步数（30 条 = 每题每步 480 次用例执行） |
| perf 轮执行 | 在线，条件触发 | 每题每 rollout 1 次大输入执行 |

### C. time_limit 标定四步

| 步骤 | 成本 |
|---|---|
| 每题造一条大输入（种子固定） | 离线 1 次 |
| 参考解在这条大输入上跑一次，量墙钟 | 每题 1 次参考解执行 |
| time_limit_ms = 墙钟 ×3（系数，Polygon 惯例）+ 下限 500ms | 纯计算 |
| 顺手用参考解算出这条大输入的 expected | 同一次执行产出 |

### D. 为什么不学 LeetCode 每用例一个钟

1. **判别力重复——correctness 轮根本不判快慢。** 用例级钟的唯一用途是区分「对但慢」，这个维度已由 perf 轮专管（10⁵ 规模 + 题级标定钟）；correctness 轮里慢解只需撞沙箱兜底钟抓病态情况。给不判快慢的轮配快慢的钟，是给自行车装转速表。
2. **RL 的 reward 需要「对但慢」的中间档，LeetCode 的二值 verdict 给不了。** LeetCode 的 TLE 是 pass/fail——超时即失败、和答错同档。训练时「对但慢」应有部分信用（0.9：比错答 0.1 强、比满分 1.1 弱），组内才有排序信号；把快慢混进每用例二值判定，等于把性能瑕疵和正确性失败搅在一起——这正是 2026-11-09 归因修正反方向修掉的东西。
3. **诊断粒度没丢。** LeetCode 用例级钟的副产品是「挂在第几条」；我们的受保护协议本来就逐条调用、带 nonce 逐条上报，哪条挂了一样看得见。

工程账（次要）：用例级独立计时要么逐用例起进程（Python 启动 ~50-100ms × 条数 × 16 rollouts × 步数，在线开销暴涨），要么在 harness 里打时间戳（可做，但回到理由 1——做了也没收益）。

一句话收束：**LeetCode 是「人交卷、判一次」，verdict 给人看；我们是「模型每步交 16 份卷、判几万次」，reward 要喂优化器——所以它混判快慢、二值输出，我们拆两轮、分档输出，钟只配在判快慢的那一轮。**

### E. 种子确定性重建

伪随机种子固定 → 生成序列唯一 → 重建出与当初逐字节相同的大输入。只存几个字节的种子、不存 MB 级输入本体（数据行不膨胀）；同题各步、各 rollout 拿到的大输入严格一致——钟和考题都不漂移，reward 含义稳定。代价：生成器代码锁版本（一改，重放出的输入就变了）。

### F. LeetCode 机制（平台通识，仓内无证据文件）

每用例一个钟 + 语言乘数（同题 Python 比 C++ 拿到更宽的钟）；逐用例执行、超限即中断并报「挂在第几条」（TLE）；**从不分析复杂度**——题面里「O(n log n) 以内」的要求靠「输入规模 × 时限」隐式执行。

### G. 扩容三段式与参数（D13 补参）

- 用例三段式：**题面样例 + 数值边界 + 随机**；随机必过 validate——LC53 拒空数组，有序/唯一/树合法这类语义约束随机数会大量违反，被拒是正常损耗不是 bug。
- correctness 轮随机输入长度上限 **1000**（10³ 量级 oracle 全程跑得动；抓慢解是 perf 轮的活，O(n²)@1000 毫无压力）。
- 入 GT 的 accepted 目标 **10~30 条** + perf 轮 **1 条**大输入；D13 的 40-80/200/1000 是**候选池**口径（生成后筛选），不是入 GT 条数。
- 判分成本 = 条数 × 16 rollouts × 步数——体量给 perf 轮，覆盖给 correctness 轮。
- **G 块补注（2026-11-13 同日规格修正）**：D13 补参的「扩容不达标告警」取数点必须在幂识别**之前**（原生解析 `bound_raw` 对账，`bound_raw < 1000 且难度 ≥ medium` 计数；生成与判分仍用幂识别值）。原理：幂识别把坏值在解析边界统一修好、下游全部看不见（掩盖效应）——告警若取修复后的值（旧设想「目标 1000 被 validate 拒到 ≤105」）在幂识别管线里永不触发，是死信号；检测必须坐在解析器之前。运行时 verifier 本来就不读约束（correctness 轮只看测试、perf 轮只看离线标定值）——「扩容看得见、verifier 看不见」的对立不存在，存在的是「修复前的坏值一致可见、修复后的一致不可见」。（2026-11-14 精确化：**打分环节** correctness/perf 不读约束；**validate 门读**——见 D22 三门。）

### H. 超约束输入的赋分与处置（D21）

| 粒度 | 机制 | 归属场景 |
|---|---|---|
| **用例级隔离** | 超约束输入不参与对错判定，记 `beyond_contract` 仅供诊断；分数由合法用例集合决定 | 承诺外输入（本场景） |
| 样本级掩码（D15） | 故障样本分=组内有效均值 → advantage 恰 0 | 判题基础设施故障专用 |
| 整题跳过 | 不判分，进跳过计数 | 约束本身错了（105 案例）——计数是发现信号 |

0 分 = 「考了且判错」= 还是罚；掩码是样本级、管组内 advantage 的，粒度对不上。隔离是「这条不算考题」。原则：**承诺外的输入不罚**（先给信息再罚不达标）。超约束输入的三个正当用途：环境探针、perf 标定、oracle 对拍——诊断用，不计分。

### I. 语义边界：放弃预造，改错解反推（D17 修订）

判分器是**无语义的比对器**：看到 (input, expected, output) 三元组，输出对得上就过。「判分器能拦语义错误」有个隐藏前提——测试集里已存在区分输入；用这个前提证明「不需要造语义边界测试」是循环论证（区分输入就是语义边界测试本身）。BC-02 的 wrong_empty 在 3 条正数样例 + 10 条随机补测上输出与正确解恰好相等，最后是全负边界（变异体引导反推）抓住的。

修订：放弃「LLM 起草预造 + 双向对拍」的预造路线（贵且盲），改**错解反推按需补**——审计/错解池里存活的错解，其区分输入就是漏掉的语义边界。先例：wrong_empty 的全负边界、increasing-triplet 的 `[1,0,-2,-2,2,2]`。数值边界（机械推导）与随机扩容照旧。

### J. expected 分层信任链（交叉点 = 实测耗时，非固定 n）

```text
小域（oracle 实测耗时在预算内，如 ≤ 数秒）
  → expected = oracle(input) 直出          ← 唯一终审
大域（oracle 跑不动，如 O(n²)@10⁵）
  → 先让 oracle 在小域验收参考解（多输入对拍全过）
  → expected = 参考解(大input)             ← 信任链传递
```

correctness 轮上限 1000 时多数题 oracle 全程够用；perf 轮 10⁵ 参考解接棒。需要大输入 expected 的量很小：perf 轮每题只重建一条。

### K. 三角色话术（为什么要有参考解）

- **oracle 管对不对**：傻解法蠢到显然对，小输入上 expected 的唯一终审。
- **参考解管快不快 + 错得像不像模型**：① 大输入 expected（信任链）；② `time_limit_ms` 标尺——必须量「正确且高效」的耗时，傻解自己超时，当不了标尺也当不了探针；③ 环境探针（「参考解同分=环境实锤」的执行者）；④ 错解池母体——变异参考解=聪明解的边界失误，与模型真实错误分布**相交**；变异 oracle=傻错误，与模型分布**不相交**，检出率是假安全感。
- **actor 是被考的人**：唯一被判分对象；输出是错解池第三源（真实错误分布）。

收束句：**oracle 管「对不对」，参考解管「快不快」和「错得像不像模型」，actor 是被考的人——缺一个，错解池就瘸一条腿。**
