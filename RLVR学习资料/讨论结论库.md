## 2026-11-09 · 为什么答错还能拿正的 reward（0.1）— D3/D15 配套论证

**定案关联：** 补强项 9 档位；03 advantage 节已收录压缩版。

**核心输出（三问机制 + 实测）：**

```text
判分方对每次作答只问三个问题：
  ①这是合法输入吗？ ②程序交出了可判定的输出吗？ ③输出等于期望吗？
  ①✗ → 这条不算数（隔离）      ②✓③✗ → 答错（0.1）
  ②✓③✓ → 通过该输入
  ②✗（判分方超时杀）→ 只是慢（0.9，性能瑕疵）
  ②✗（程序自己崩）→ 也算输（0.1，交白卷）
「答错」统一定义：在合法输入上产生了可判定的错误输出。
超时 vs 崩溃同是「无输出」，分界在责任方：判分方没收卷（慢）vs 程序弃考（输）。
```

GRPO 平移不变实测：`[1.1,1.1,0.9,0.1×4,−0.1]` 整体减 0.2，advantage 逐条不变——绝对值中性，只有组内排序与档间间距有意义；混合组正 reward 错答 advantage = −0.635（被推远）；全错组 ±0.935 全是格式信号（课程效应）。

## 2026-11-09 · 600 秒管理器超时的来源与可标定性 — D15 配套论证

**核心输出：**

```text
最坏合法墙钟 ≈ (批大小 ÷ 线程数) × 沙箱限时 = 256 ÷ cpu_count × 30s
  32 核 ≈ 240s（600 够）；8 核 = 960s > 600（全组顶满沙箱时会误伤排队样本）
smoke test 标定法（与 perf 同构）：全死循环批次实测最慢单样本墙钟 × 安全系数
  → manager_timeout_s；现版有重试，按重试后口径标定。低核节点进「实跑前必查」。
占位值对拍（GRPO 同款公式，[0.1,0.1,0.1,占位]）：
  0.0 → [+0.5,+0.5,+0.5,−1.5]  错答被奖励（BC-10）
  0.2 → [−0.5,−0.5,−0.5,+1.5]  占位样本拿全组最强正信号（std=0.05，绝对差距活不过标准化）
  0.1 → 全同分 ≈ 0              「未知」被主张成「等于错」
  单条掩码 → 故障样本恰 0        「不知道」的正确表达（D15 落地）
本质：占位值不是分数是认知状态；任何具体数值都在替未知质量伪造主张。
```

**状态：** 0.2→+1.5 对拍已入 03/补强项 6；600 的排队公式与 smoke-test 标定法未入正文（候选：02 执行边界/训练 README 实跑前必查）。

## 2026-11-10 · 三指标归属与拦截率的拆轴归因 — D13 §2 配套

**核心输出：**

```text
必需语义项/边界覆盖率 → 纯数据面：考题全不全（对清单打勾，verifier 不参与）
测试区分力（错解池）  → 数据面：考题狠不狠（对每个已知错解存在能区分它的测试）
判分保真度            → verifier 面：阅卷准不准（能区分的必拒 + 正确解零误杀）
拦截率 = 测试区分力（数据）× 判分保真（verifier）——联合属性，低了先拆轴：
  固定 verifier 换测试集 → 变了 = 缺测试（扩容闭环）
  固定测试集换 verifier → 变了 = 判分缺口（修协议/比较器）
两轴铁证：wrong_empty（同 verifier 补测试后拦下——数据轴）
          early_exit（同测试集换受保护协议后拦下——verifier 轴）
快捷视角：逐题拦截差异几乎全来自数据（verifier 是通用机器、题目特异性全在数据行）；
          verifier 的缺口表现为跨题系统性模式（bad case 库按层登记的就是这些）。
```

<a id="lib-oracle-position"></a>

## 2026-11-10 · oracle 的定义与作用位置 — D16 配套

**核心输出：**

```text
oracle = 独立于被验证对象的答案求解/核对器。三关键词：独立（与被审对象不同源，
否则互证一起错）、求解或核对答案（算 expected / 对答案）、它自己不判分。
作用位置：只在离线数据侧（造样例算 expected、审参考解、扩容终审）；
不进在线 verifier——意志以 expected 字面量冻结进 GT（assert 里的 -2 就是它定的），
在线判分只比较候选输出与冻结值，从不跑 oracle。
为什么不在线：成本（傻解法跑不动大输入、每步 256 次判分现算爆炸）＋
稳定性（冻结值可复现、判分标准不漂移，oracle 自身故障被挡在判分路径外）。
口诀：oracle 是出卷时的标答制定者，verifier 是阅卷时拿印好答题卡的比对者。
```

**状态：** 压缩版已入 01 次图③旁；本条为完整版。

## 2026-11-10 · 错解池三源辨析：变异体 / 语义错解 / 模型真实输出 — D18① 配套

**核心输出（三源各补一块错误分布，缺一块就是盲区）：**

```text
变异体     ＝实现级失误：题意理解对、代码写错（边界差一、比较符错）。
            操作发生在代码上（单点改动），得到的只是「疑似错解」——要找到
            合法输入使其输出 ≠ oracle（可信反例）才算确认；找不到反例的
            标「未定」，不算错解（可能是等价变异）。「每个都带可信反例」
            就是这道入池门槛：变异性 ≠ 确认性。
语义错解   ＝题意级偏差：代码完美实现「另一种题意理解」——wrong_empty 对
            「允许空子数组」的题是满分实现、wrong_sum 理解成返回总和。
            变异造不出它：变异只在参考解的代码结构里小改，参考解里根本
            没有那种理解的代码可改。
模型真实输出＝分布真样本：训练/采样时模型的真实回答，尤其是恰好骗过现有
            测试的错答案（特判样例的解、reward hacking 雏形）——只有
            rollout 能产出，直指测试缺口。三源里只有这一类是模型产生的。
只用变异体为什么不够：池子要近似模型真实错误分布——模型既犯实现错、也犯
题意误解、还会发明特判；只放变异体，100% 检出率只证明「能抓实现级失误」，
对题意级错误是盲的——假安全感（D18① 错误分布匹配的延伸）。
```

**状态：** 已入 01 主图扩容带判据②（压缩版）；本条为完整版。

## 2026-11-10 · 语义错解的造法、escaped 错解的挑法与双盲漏检的有界化 — D13 §6 配套

**核心输出：**

```text
语义错解四造法（全部过 oracle 反例门槛；反例＝区分两种题意理解的输入）：
  ①歧义清单系统枚举（主力）：空输入？区间开闭？任意解/最优解？多解顺序？tie-break？
    取模？——逐项写「按另一种理解实现」的解；wrong_empty/wrong_sum 出自此清单
  ②LLM 生成误读（读题面枚举合理误读，产出是候选仍要反例确认）
  ③人写（试点题与高风险题）  ④真实错误回填（越训越准）

escaped 错解（错但拿满分）三挑法——关键是重判必须用没参与过训练判分的新输入：
  ①新输入重赛（核心）：满分回答分层抽样，用刻意留出的审计输入集（D13 §6）
    再考——新卷上露馅即实锤，暴露输入进回归测试
  ②oracle 重判：抽中回答在新生成输入上对拍 oracle（离线，证据规模不限）
  ③统计侧写找可疑点：突然全组满分而历史低通过率；reward 涨 dev 不涨；
    同题多条满分解在新输入上行为不一致

双盲漏检（verifier 没拦 + 审计没看）——结构性风险，目标是有界且递减而非零：
  ①多层漏斗：训练判分→审计新卷→held-out 评测→效果归因；层层独立，漏过需相乘
  ②污染有缓冲：组内区分度筛题（0<c/n<1）保证对错混合——错解只骗过测试的那组
    拿正 advantage，污染有限且随测试增强递减
  ③闭环回报：每个被发现的 escaped 错解的暴露输入进回归测试，同类漏检单调下降
  ④统计上界：300 个满分错解零漏判 ⇒ 漏判率 < 1%（95%）——把「不知道有没有」
    变成「知道有多少」
根除不可能（有限证据的认识论限制）；逼近零靠外循环——新测试持续注入、
人工/更强模型复核、red team 对抗（工业 data flywheel 同构）。
```

**精确化（2026-11-10，用户追问「GT 不是从没给模型看过吗」）：**「泄题」比喻在信息层不成立——
GT 内容模型确实从没见过（判分隔离已防住**信息泄露**）。真正泄的是**目标**：测试集定义 reward、
reward 是优化目标，「过/不过」一个 bit 就足以塑造策略——与正确解在现有测试下同分的错解拿到
同样的正 advantage、被一起强化（选择压强≈背题，但无信息传递）。held-out 输入的理由精确表述：
参与过判分的输入测「对代理指标的拟合度」，held-out 输入测「真·正确性」——即 train/test split
的 Goodhart 版论证。两种泄露对照：信息泄露→判分隔离可防；目标泄露→只能靠 held-out 缓解。

**状态：** 未入正文（候选：测试扩容方案 §6 旁 / 04 归因节；D13 §2「获奖励程序的复审错误率」与 §6 已覆盖机制骨架，本条补方法与边界论述）。

## 2026-11-10 · 冒烟门控晋升协议：审计闭环跑在 smoke 里，达标才上正式训练 — D19

**核心输出：**

```text
为什么放 smoke：真实 rollout 才产生真实错误分布（模型真实输出这一源只有真训练能给），
smoke 是最便宜的「真实环境」；把测试盲区在花大钱之前压掉。

预注册判据（开跑前写死）：
  escaped 率 = 满分回答在 held-out 输入上的失败比例   （要 ≤ X%）
  误杀率     = 正确解被拒比例                         （必须 = 0）
  样本量绑定置信度（rule of three：0 漏判 / N 样本 → 95% 上界 ≈ 3/N）：
    N=20 → ≤14%   N=60 → ≤5%   N=300 → ≤1%
  冒烟用粗阈值（如 N=60、≤5%、误杀 0）；<1% 的硬上界只能靠正式训练期审计补。

循环：smoke 跑 → 审计满分卷（held-out 重赛 / oracle 对拍）→ 五条反馈路
（回归 / 定向扩容 / 清单修正 / 训练决策 / 不动）→ 重跑，直到达标。
晋升：冻结 test_version 作正式 GT；审计不停止（正式训练期与之后继续抽检——
模型变强会出新错法，smoke 达标只是准入证据，不是终身保证）。
预算内不达标：记缺口带风险标记进入或缩小规模；不无限循环、不假装达标。

三个容易糊掉的点：
  ①「失败率」必须定义成 escaped 率（不是 reward、不是测试失败率），且与样本量一起写死；
  ②承重前提是测试可再生（D16/D17），否则 held-out 用一次就废；
  ③冒烟模型 ≠ 正式模型，阈值可迁移的是「准入判断」，不是「性能承诺」。
```

**补充（2026-11-10，用户问 n 与样本量、强模型 vs base）：**
```text
n：原版 16（256 条/步）；你的推演 8；冒烟 8~16（base 弱用 16 + 筛题）。
样本量（精确二项 95% 上界）：
  N=60,0 漏 → 4.9% 可停   N=100,0 → 3.0%   N=100,1 → 4.7%
  N=100,2 → 6.2% 不通过   N=100,4 → 8.9%（点估计 4% 也不算过）
  提前停必须卡 N=60（30 个 0 漏的上界 ≈9.5%）；满分样本跨步累计、按题分层。
强模型 vs base（同时做、顺序固定）：
  测试质量 = 策略无关 → 强模型离线对抗审计（产量高、错误形态接近聪明解；
    测试必须在至少与未来正式模型一样强的对手面前审）
  escaped 率 = 策略相关 → base 冒烟（真实风险；N 不够就报证据弱，不凑阈值）
  误杀率 → oracle/已知正确解，不需模型
  时序：冒烟前强模型审计冻结 v1 → 冒烟中审计→v2 → 晋升 → 正式训练期继续抽检
```

**状态：** 已入 D19（压缩版）；本条为完整版。未入 05/测试扩容方案正文（候选：正式训练计划节）。
