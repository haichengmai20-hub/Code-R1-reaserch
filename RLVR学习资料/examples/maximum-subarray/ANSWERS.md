# 提交后的答案与评分依据

[操作说明](EXERCISES.md) · [资料首页](../../README.md) · [综合通关](../../04_真实训练与独立评测.md#graduation)

完整示范可以照着理解，独立题先提交再看。自动结果只核对数据、数字、类别与装配；下面的理由、源码定位和因果解释要人工检查。参考答案不是你的实跑经历。

<a id="data-rubric"></a>

## 数据、配对与GT

合格解先按题意定义“非空连续子数组”，列出小输入全部合法子数组或证明穷举覆盖，再取最大和，核对范围与整数类型。参考实现结果一致是附加证据；相似实现一致、hash正确、JSON能解析都不能独立证明expected。

seed模式3条accepted、0条quarantined、0条pending，wrong_empty可1.1。补已核对全负输入后，wrong_empty应0.1；reference仍1.1。只有坏expected的全负行被隔离、没有正确全负行进入GT时，旧错误实现仍可能高分。这说明审核和测试覆盖各有作用，不表示整个Task报废。

新增正确行不受8/7限制。读回GT必须含自己的case_id/input/expected，坏行不出现，case_index一致；test_version随GT变化。相同输入的正确与错误记录分别保留/隔离。合法大输入pending说明小Oracle预算不足，不能认作非法输入或给模型负奖励。

2分：自己的输入与完整独立依据、新GT和实际读回齐全；1分：靠提示得出答案或缺一项证据；0分：把reference/hash当认证、丢弃正确同输入行或没有实际装配。原运行前缀与actor题目不能混用；GT里的整数不是模型要模仿的回复。

<a id="blind-rubric"></a>

## 未知类别故障

按证据分类，不背record编号：

| 观察 | 优先责任层与解释 |
|---|---|
| 入口与题目接口不一致 | Task契约；先核对源签名，不能运行失败就归模型逻辑 |
| 合法输入配出的expected与完整求值不符 | Tests；保留该输入正确配对，不据坏答案指控候选 |
| 已接受配对与GT中的值不一致 | GT装配；再算答案不会自动修复编码串位 |
| 声称正确却缺完成载荷，或实际值错误 | Verifier/评价解释；计数齐全仍需结果，reward1.1不足 |
| k>n或报告值不符合(n,c,k) | Evaluation协议或聚合；不能报告不可计算k |
| 接口、答案、装配、结果与指标全对应 | none；不要因为这是故障题就强行找错 |

一条记录可有多个责任层。坏expected需先修数据，不直接把基于它的候选差异当模型失败。2分要求每个类别都有字段证据、竞争性解释和最小区分检查；只有类别对、理由空泛最多1分。自动all_categories_match不代替这项判断。

<a id="transfer-rubric"></a>

## 两数之和

题意允许任意顺序。A原顺序：legacy/semantic都通过；B反顺序：legacy失败、semantic通过；C先把当前值写入seen，可能复用自己索引：两种比较均失败。这些是固定程序的有限seed结果。

完整判定：返回列表长度2，索引是真正int且范围内，两索引不同，对应元素之和为target。bool在Python可等于整数，所以不能只用宽泛isinstance或列表==；set会丢长度与重复信息，sort只改善顺序。题目唯一性指有效索引对，不限定排列。

新GT封装并经A/B/C正负回归，同时保留原source/test与新test_version。它改判定器，不是模型训练；此functional拼接仍不能防提前退出。2分需要独立推导完整条件、实际两版GT和反例；只照抄“排序后相等”不合格。

<a id="mechanism-rubric"></a>

## 机制推导与变式

完整示范两类logits `[0,ln3]`，T=1选第二类，p=0.75、logprob≈-0.287682。old固定同值，A=0.5，ratio1、loss-0.5。对logits的梯度 `[0.125,-0.125]`；SGD学习率0.1更新为 `[-0.0125,ln3+0.0125]`，选中概率上升。解析梯度与有限差分一致验证这个toy公式，不证明torch/真实模型更新。

未裁断时logprob导数为 `-A*ratio`，再乘选中token log-softmax的导数。正A、高ratio裁断PG；负A、低ratio裁断PG；另两种越界方向仍需纠正。PPO目标clip与梯度范数clip分开。new==old数值相等不意味着梯度0；old也带同一new梯度会错误抵消。

old/ref/advantage冻结；new forward带梯度。判题reward不必可微。因果模型前一位置预测后一token，本源码截 `-R-1:-1`；温度在概率重算也使用。T=2时本示范p约0.633975，不能把greedy的0代入训练除法。

两回答token loss +1/-1、长度2/6，同micro平均-0.5，逐回答或两个等权micro平均0。源码在micro内做masked_mean，再累积；不是所有mini token统一平均。EOS=9，`[3,4,9,0,0]` mask=[1,1,1,0,0]；无EOS全1，pad/EOS不同且缺真实长度时pad也可全1。mask无法独立证明正常停止。

2分：自选变式手算、冻结量与方向正确，给出独立数值核对、源码函数与反例；1分：能照报告解释但变式/边界不全；0分：梯度经执行器、old/ref角色混淆或概率错位。当前机制lab省略KL以隔离PG，课程里仍需解释actor new/ref KL与reward old/ref KL的不同作用。

## 综合复核与面试追问

按04的0—2分表，至少8/10、前四项无0、关键机制错误全部修正。评分依据要有原回答、对应证据、返工与复测；只补一个“通过”标签不算验收。隔日再讲一次机制并现场定位两处函数。

可随机追问：为什么源码的extra_info.prompt不能随意删？为什么超时0不等于算法错？为什么loss0仍可能有梯度？为什么换micro可改权重？为什么随机回答变了不证明同步？为什么恢复模型不保证位级续训？为什么同seed不排除小样本波动？每次答机制、实现、反例和证据范围。

效果题合格回答给出固定协议、按题配对baseline/新checkpoint、预登记重复seed、失败/infra政策与成本；开发集选checkpoint，最终测试独立。有限池组合值和增大k不能被讲成学习提升。真实运行证据未具备就诚实记录准备完成/待实跑，不能虚构经历。
