## 诊断 → 修 → 验证

| your-01 的诊断 | 证据 | your-02 的改法 | your-02 里的验证 |
|---|---|---|---|
| 存盘后判题故障 | 第 65 / 129 / 193 步紧跟 `timing_s/save_checkpoint`；`timing_s/reward` 64–69 秒（平时 25 秒）；控制台 15 条 `sandbox start timeout`，作废 4 组；`rewards/min` 仍 −1.1、ppo_kl / clipfrac 不动，所以不是模型的问题（[notes/incident_report.md](notes/incident_report.md)） | 判题临时目录从 `/data/tmp/judge` 改到 tmpfs `/dev/shm/judge`，不再和 checkpoint 写回抢同一块盘 | 第 257 / 321 / 385 步 `timing_s/reward` 25.0 / 23.5 / 27.5 秒，`neutralized_groups` 全程 0 |
| 验证集就是最终评测集 | v2 test 既用来每 16 步选 checkpoint，又用来报结论 | 从筛后的题里切 200 题当验证集；dev 和 LCB held-out 只在第 400 步评一次 | held-out 上 your-02 对 your-01 净胜 8 题（9 赢 1 输，+5.6 个点），seed 噪声约 ±1.3 个点；dev 上 +3.0 个点同方向 |
| 熵系数 0，熵 1.14 → 0.30 | 前 60 步从 1.14 降到 0.42 是格式锁定，之后缓降到 0.30；采样 pass@8 仍在涨（0.768 → 0.870），没有被诊断出的问题 | **不改，留作观察项**（计划里的 `clip_ratio_high` 0.28 去掉：没有证据的预防性改动会让归因更乱）| 续训 200 步熵 0.29 → 0.28（第 300 步附近最低 0.26），没再塌；pass@8 0.870 → 0.898 仍在涨。掉到 0.2 以下或 pass@8 掉头再上 clip-higher |
| 全同组白占步数 | 第 200 步每步 9.6% 的组全对、5.7% 全错，这些组 advantage 为 0 | 用第 200 步采样 8 条/题筛题：去掉全对 158、全错 124 | 第 201 步全对 5.0%、全错 3.6%；到第 400 步全对又回到 10.4%（模型变强了），筛题是周期性的事，不是一次性的 |

两处要诚实写的：没有做消融，your-02 比 your-01 多出的 +5.6 个点里，多训 200 步和三处改动各占多少分不开（参考 run-02 也是这样）；筛题去掉的全对题（158）和全错题（124）差不多多，所以第 201 步的 reward 几乎没跳（0.569 → 0.553，在噪声内），「台阶」比第七环预想的小。

- **10-17** 写 [eval/protocol.md](eval/protocol.md)；LeetCode 去污染版 parquet 沿用参考目录的那份；判分探针与参考目录相同。
- **10-18 08:00** your-01 启动（[config/your-01.sh](config/your-01.sh)）。第 0 步验证 −0.166：贪心 200 题只过 50 题，86 题（43%）格式错——标签缺失或循环到 6144 被截断，Base 还不会按系统提示写 `<think>…</think><answer>…</answer>`。第 1 步 reward −0.278，`rewards/max` 1.1、`min` −1.1，判题在跑；128 条里 57 条格式错（其中 18 条截断）、20 条通过。

- **10-19 04:08 / 04:16** 第 192 步存盘，第 193–194 步第三次（作废 4 组、2 组）。第 192 步验证 0.559（通过 99）。
