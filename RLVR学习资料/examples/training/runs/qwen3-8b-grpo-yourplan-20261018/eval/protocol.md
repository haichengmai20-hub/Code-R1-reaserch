# 评测协议（你的方案；2026-10-17 预登记，训练前冻结；10-19 补 held-out；10-20 第二轮换验证集）

你在第二环决定不做 held-out、用 v2 test 当最终评测；第六环看到 your-01 的结果后决定补一栏 held-out；第七环决定第二轮不再用 v2 test 做训练中的验证：

| 集合 | 来源 | 题数 | 用途 | 能否用于选 checkpoint |
|---|---|---|---|---|
| dev | LeetCodeDataset v2 test（补强版 GT，带运行前缀） | 200 | your-01 每 16 步贪心验证并选 checkpoint；两轮结束后离线评测 | your-01 能；your-02 不能（只在第 400 步评一次） |
| val200（第二轮新增） | 从筛题后的 1607 题里随机切出，训练集去掉它们 | 200 | your-02 每 16 步贪心验证；与训练分布一致 | 能 |
| held-out（第六环补做） | LiveCodeBench 中 contest_date ≥ 2025-05-01 的题（晚于 Qwen3 系列的数据截止），平台 leetcode / atcoder / codeforces，与参考目录同一题单 | 142 | 只评基线、your-01 第 200 步、your-02 第 400 步各一次；不用于选 checkpoint；结论以它为准 | 不能 |

**离线评测口径**（与参考目录相同，便于对照；基线是 Qwen/Qwen3-8B-Base，用与训练相同的 Code-R1 系统提示）：

| 项目 | 设置 | 输出 |
|---|---|---|
| 贪心 pass@1 | temperature 0，max_tokens 8192；聊天模板与训练时同一套（Qwen3 的 ChatML 模板，assistant 段不预填，`<think>` 由模型自己写；Base 的 tokenizer 是否自带这套模板，实跑前 smoke 时核对） | 每题一条，通过 / 失败 / 格式错 |
| 采样 pass@1、pass@8 | temperature 0.6，top_p 0.95，top_k 20，n=8，seed ∈ {1, 2, 3}，max_tokens 8192 | 每题每 seed 8 条；pass@1 取 8 条平均，pass@8 取任一通过 |
| 配对比较 | 同一题两模型的贪心结果配对，数赢 / 输 / 同 | 净胜题数与百分点；your-02 对 your-01 的配对是第二轮的主结论 |

**三个口径差异：**

- 训练中的验证用回答上限 6144，离线评测用 8192，而且验证记的是 reward 均值不是通过率。your-01 第 0 步验证 −0.166（通过 50 题 = 0.250，格式错 86 题 = 43%）与基线离线贪心 0.380（76 题，格式错 18.5%）差在上限和口径。
- your-01 的验证集就是 dev：用它选 checkpoint 再用它报结果，结论偏乐观；所以补了 held-out、只评一次、不回头选 checkpoint。your-02 改用 val200 后，dev 只在最后评一次，这一条限制在第二轮不再存在。
- val200 来自筛题后的题集（去掉了全对和全错的题），难度比 v2 test 集中、起点更高（第 200 步 0.634 对 v2 test 的 0.559），两条验证曲线不能直接比高低；比的是各自的走势。
