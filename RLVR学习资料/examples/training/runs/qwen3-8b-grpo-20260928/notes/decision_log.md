# 决策日志：七个环节各决定了什么、依据是什么、后来怎么看

每一环三栏：当时的问题、决定与依据、事后评价。用于复盘，也用于 05 的作业模板。

## 一、机器

| 问题 | 决定与依据 | 事后评价 |
|---|---|---|
| 几张什么卡 | 4×A800 80GB 单机（个人研究能租到的量级）。算术：actor fp32 参数+梯度+Adam ≈ 16 B/参数 × 8.19B = 131 GB（Qwen3-8B-Base 与 Qwen3-8B 同架构），4 卡分摊 32.8 GB/卡；vLLM 占每卡 50%（40 GB），0.8.5 的 sleep mode 训练时必须释放，否则放不下；激活开梯度检查点。8×H100 能把 76 小时压到 20 小时上下，但个人研究租不起也说不过去 | 对。生成占每步 19%（162 s / 856 s），更新占 51%（438 s）；Base 的回答短（均值 1,000–1,800 token），生成比预想的快。日志里 `perf/max_memory_allocated_gb` 约 56–57 GB，和算式（32.8 + 4.1 + 激活 + logits）对得上 |
| CPU 和磁盘 | 128 逻辑核；根盘 300 GB，数据盘 3.5 TB | **错**：checkpoint 放根盘，第 128 步写满。应一开始就放数据盘并限保留份数。v0.4.1 的 prime 固定 64 个判题进程，128 核够用 |
| 费用 | ¥10/卡时 × 4 = ¥40/h；run-01 预算 4 天 | run-01 76.1 h ¥3,043（$423），run-02 100.6 h ¥4,023（$559），评测与环境约 ¥400，合计约 ¥7,500。Code-R1 的配方（n=16、320 步）在个人卡上是 3 天多；run-02 回答上限翻倍、每步 4 次更新，4 天多 |

## 三、框架搭建

见 [framework_port.md](framework_port.md)。决定：迁到 verl v0.4.1 并移植判分；四项检查全做。事后评价：对；Base 循环到上限的风险当时看到了（smoke 的 5 条样例里 1 条顶到上限）但没处理，留给了 run-01。两条 v0.4.1 的断言后来都撞上了：`train_batch_size >= ppo_mini_batch_size`（所以 Code-R1 原脚本的 256 写不进去，run-01 只能写 16）和 `max_num_batched_tokens >= prompt + response`（run-02 改 8192 时必须同步提到 12288）。

## 四、参数配置（run-01）

| 参数 | 值 | 依据 | 事后评价 |
|---|---|---|---|
| train_batch_size × n | 16 × 16 | 照 Code-R1 | 可以 |
| max_response_length | 4096 | 照 Code-R1；Base 会循环到上限，但想先看截断率 | **部分错**：开局 23% 截断，到 320 步仍有 5.6%；但格式失败的大头是标签缺失（第 1 步 54% 格式失败里 30% 是没写标签），上限只管循环那一部分。前 64 步的 reward 增量 85% 来自学会格式和停机，不是学会解题 |
| temperature / top_p | 1.0 / 1.0 | 训练要探索 | 可以 |
| lr | 5e-7，无 warmup | 照 Code-R1 | 可以。v0.4.1 下 warmup 为 0 时第一步 lr 就是 5e-7，320 步 320 次更新（旧版 fork 才有第一步 lr=0 的坑） |
| KL | low_var_kl，0.001，进 loss | 照 Code-R1 | 可以：到 320 步 kl_loss 0.065。Base 起点要从头学格式、停机和思考结构，策略离 ref 走得远是正常的；系数 0.001 下它只是保险，没有失控 |
| entropy_coeff | 0.001 | 照 Code-R1（v0.4.1 默认 0） | 熵 1.10 → 0.32：前 60 步的快速下降是格式锁定（乱写和循环消失），之后缓慢；采样 pass@8 0.768 → 0.890 在涨，不是坍缩 |
| ppo_mini_batch_size | 16 题 | v0.4.1 断言它不能大于 train_batch_size，16 已是上限；每卡 16×16/4 = 64 条正好一个 mini-batch | 每步只 1 次更新，`pg_clipfrac` 恒 0、`ppo_kl` 恒 0，clip 没起作用。梯度累积 64/4 = 16 个 micro 全在，没有缩放，grad_norm 起点 0.83、前 64 步降到 0.55 左右、之后 0.30–0.60，是真实量级 |
| reward_manager | prime | v0.4.1 原版 | **错**：故障记 0.0 污染组内统计 |
| 验证 | 每 16 步贪心 n=1，回答上限同训练 | 省时间 | 验证数字受截断影响，和离线协议不可比 |
| 保存 | 每 64 步，不限份数，放根盘 | 想全留 | **错**，见事故 |

## 五、训练曲线解读（run-01）

| 看到 | 判断 | 处置 |
|---|---|---|
| 第 1–64 步 reward -0.409 → 0.393，格式失败率 0.536 → 0.079（其中截断 `response_length/clip_ratio` 0.229 → 0.068），长度 1,787 → 1,005 | 主要是格式学习：模型学会写 `<think>…</think><answer>…</answer>` 并在 4096 内停下 | 拆分确认：0.802 里 0.678 是格式 |
| `pg_clipfrac` 恒 0，`ppo_kl` 恒 0 | 单 mini-batch 且 ppo_epochs=1，new 就是 old | run-02 改 mini-batch 4 |
| 第 129–134 步 reward 掉到 0，`rewards/min` 0.0，`timing_s/reward` 掉到 2–7 秒 | 判题故障被记 0.0，不是模型坏了 | 查日志，见事故报告 |
| 第 131–160 步 KL 从 0.050 跳到 0.061、格式合格者的正确率 0.50 → 0.47 | 污染的 advantage 推了错方向 | 不回滚，观察恢复（第 160 步 0.52） |
| 第 192 步后 reward 0.52 → 0.56 走平，全对组 4.4% → 6.0%；用第 192 步 checkpoint 采样 8 条/题，19% 的题全对或全错 | 这些题没有组内信号，白采样 | run-02 筛题 |
| 熵 1.10 → 0.32（前 60 步快降，之后平稳），长度 1,787 → 900–1,000（第 30–64 步的谷底）→ 1,517 回升 | 正常：先降是循环被罚掉，后升是思考变长；没有长度爆炸 | 观察 |

## 六、评测

| 问题 | 决定 | 事后评价 |
|---|---|---|
| 协议何时定 | 训练前写死：dev / held-out / extra，解码参数，seed，配对比较 | 对 |
| 贪心还是采样 | 两个都报；Base 的贪心回答两成是循环或标签缺失，所以验证只看趋势，结论用配对加采样口径 | 对：LCB 采样 std 0.005–0.015，两轮对基线净胜 16 / 26 题远超噪声；run-02 对 run-01 的 +7.0（净胜 10 题）也超过 3 倍标准差，dev 上的 +2.0（净胜 4 题）则分不出 |
| max_tokens | 离线一律 8192 | 对，否则 run-01 的模型会因截断吃亏 |
| 看哪个数选 checkpoint | 只看 dev | 对 |

## 七、归因与优化

| 结论 | 证据 | 改动（run-02） | 结果 |
|---|---|---|---|
| run-01 的训练 reward 大半是格式分 | 拆分表：第 1–64 步 0.678 / 0.802 | 回答上限 8192，`max_num_batched_tokens` 提到 12288 | 开局截断 6.7%（run-01 22.9%），但标签缺失仍 30%，第 1–64 步增量里格式仍占 78%：上限只管循环，标签要靠训练学 |
| 全对或全错的题白采样 | run-01 到 320 步全对组 6.0%、全错组 1.4%；第 192 步采样 8 条/题：198 题全对、155 题全错 | 去掉这 353 题剩 1536；epochs 提到 4 | 全错组开局 14% → 320 步 0.8%，全对组又涨到 10.1%；dev +2.0（0.615 → 0.635，净胜 4 题，分不出），LCB +7.0（净胜 10 题） |
| 判题故障污染 | 事故 | prime_plus 整组作废，checkpoint 换盘 | run-02 两次作废，曲线无痕 |
| clip 没起作用 | clipfrac 0 | mini-batch 4 题，每步 4 次更新 | clipfrac 2–6%，ppo_kl 约 6e-4，grad_norm 0.80 → 0.24 |
| dev 增益大于 held-out | run-01 dev +23.5，LCB +11.3 | 测试弱（只有样例），dev 偏乐观；held-out 才算数 | run-02 对 run-01：dev +2.0 分不出，LCB +7.0、净胜 10 题、只 1 题变差，超过 3 倍 seed 标准差；pass@8 0.582 → 0.695 |
| 还没做 | 困难题动得少（LCB hard 0.053 → 0.132，38 题里 2 → 5 题）；全对组到 320 步 10.1%；测试没增强；长度 2,122 → 2,425 还在涨 | 下一轮：`--augment_cases`、按 checkpoint 定期再筛、超长惩罚 | 未做 |
