# 训练 reward 的增量从哪来

训练 reward 的均值 = 1.1 × 通过率 + 0.1 × （格式合格但失败）比例 − 1.1 × 格式失败率，判题故障记 0.0 的样本另算。把相邻两段的增量拆成「格式变化」和「正确率变化」两部分（先固定正确率只换格式失败率，再固定格式只换正确率），数字在 `reward_decomposition.json`。Base 起点下格式失败率从 0.54 起步（标签缺失 0.30 加循环到上限 0.23），所以前 64 步的格式部分特别大。

## run-01

| 区间 | Δreward | 格式部分 | 正确率部分 | 格式占比 |
|---|---:|---:|---:|---:|
| 1 → 64 | +0.802 | +0.678 | +0.122 | 85% |
| 64 → 128 | +0.087 | +0.014 | +0.076 | 16% |
| 128 → 192 | +0.043 | +0.001 | +0.042 | 1% |
| 192 → 320 | +0.035 | 0.000 | +0.036 | 0% |

前 64 步的曲线很陡，但 85% 是「学会写标签并在 4096 token 内停下」（格式失败率 0.536 → 0.079），格式合格者的正确率只从 0.286 升到 0.418。之后格式失败率停在 0.07（其中截断 0.06），增量全靠正确率：0.418 → 0.500 → 0.546 → 0.584。整轮下来格式部分合计 +0.693，正确率部分 +0.276。

## run-02

| 区间 | Δreward | 格式部分 | 正确率部分 | 格式占比 |
|---|---:|---:|---:|---:|
| 1 → 64 | +0.652 | +0.511 | +0.140 | 78% |
| 64 → 128 | +0.098 | +0.009 | +0.091 | 10% |
| 128 → 192 | +0.082 | +0.001 | +0.081 | 1% |
| 192 → 320 | +0.051 | 0.000 | +0.054 | 0% |

run-02 也从 Base 从头训。回答上限 8192 把开局的截断从 0.23 压到 0.07，但标签缺失仍是 0.30，所以前 64 步的格式占比只从 85% 降到 78%：上限只管循环，标签要靠训练学。64 步后格式失败率停在 0.02，增量来自正确率：0.423 → 0.515 → 0.598 → 0.653。

## 全同组

`group_stats.csv`：16 个回答全对或全错的组没有 outcome 信号。run-01 开局 13% 的组全错（Base 一半回答格式错），到第 64 步 6%、第 320 步 1.4%；全对组从 0.4% 涨到第 128 步的 3%、第 320 步的 6%。run-02 筛题后开局全错 14%、全对 0.4%，到 320 步全错 0.8%、全对 10.1%——一次筛题只管一阵，难度要随 checkpoint 刷新。

## 事故

第 129–134 步的增量不进上表。第 131 步 256 条里 205 条是 0.0；第 132–134 步全部 0.0，整组同分，advantage 为 0，这三步只有 KL 和熵的梯度。
