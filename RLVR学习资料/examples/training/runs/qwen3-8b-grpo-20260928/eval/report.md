# 评测报告（2026-10-09）

协议见 [protocol.md](protocol.md)，训练前冻结。三个模型：Qwen3-8B-Base 基线（预训练模型，没经过 SFT 或 RL，用与训练相同的系统提示和聊天模板）、run-01 第 320 步、run-02 第 320 步。所有离线评测 max_tokens 8192，判分用补强版受保护协议加 firejail。结果表由生成器直接写出，见 [tables.md](tables.md)；本文只写结论，引用的数字都来自那里。

## 结论怎么下

- **基线为什么低**：Base 没学过 `<think>…</think><answer>…</answer>`，贪心回答 18.5%（dev）/ 20.4%（held-out）标签缺失或循环到 8192，被判 -1.1；采样口径下更多，所以 dev 采样 pass@1 0.352 比贪心还低。训练后的增益里有一块是「学会格式和停机」，不全是解题能力；两轮的格式失败率都降到 2% 上下，这一块两轮一样。
- **两轮都明确优于基线**：held-out 净胜 16 / 26 题（+11.3 / +18.3 个点），采样口径的 seed 标准差 0.5–1.5 个点，3 倍标准差不到 5 个点，远超。采样 pass@1 和 pass@8 也都大幅上升（held-out pass@8 0.366 → 0.582 / 0.695）：不只是贪心变准，会做的题的范围也扩大了，因为基线的 8 条采样里一大半是格式错或循环。
- **run-02 比 run-01 多出来的部分**：在 held-out（+7.0 个点、净胜 10 题、只 1 题变差，超过 3 倍标准差）和 pass@8（0.582 → 0.695，+0.11）上；dev 上几乎分不出（+2.0 个点、净胜 4 题、12 赢 8 输，在噪声边缘）。dev 已接近这套样例测试能区分的上限，两轮都在 0.6 以上；要分出两轮，看 held-out 和 pass@8。
- **按难度**：held-out 的收益集中在 easy（0.302 → 0.558 / 0.605）和 medium（0.066 → 0.147 / 0.230）；hard 只有 run-02 动了（0.053 → 0.132，38 题里 2 → 5 题），1 题就是 2.6 个点，不单独下结论。dev 上 hard 0.192 → 0.277 / 0.340（47 题里 9 → 13 / 16 题）。
- **EvalPlus**：补全式贪心评测，没有格式门，Base 本来就能做（约 0.68，按 Qwen3-8B-Base 的公开量级写，实跑前核对）；训练后 +2–3 个点，不作为主要证据。
- **验证曲线不能当评测**：训练中的 val-core 是贪心、回答上限同训练，报的是 reward 均值不是通过率。run-01 的 0.595 和 run-02 的 0.656 不可比，基线在两种上限下分别是 -0.224（4096，47% 标签缺失或截断）和 -0.096（8192，38%）；后者换算成通过率 0.260（52/200），比离线贪心的 0.380 低 12 个点：Base 没学过格式时，哪条循环、哪条漏标签对 prompt 过滤、批内拼接和算子实现都敏感，两套跑法下的贪心结果本来就不可比（差距比后训练模型大得多），所以 val-core 只看趋势，结论以离线协议为准。
