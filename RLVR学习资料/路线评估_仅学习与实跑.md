# 路线评估：仅学习 vs 实跑，各要补什么、能学到什么、面试能答到哪

**资料导航：** [资料首页](README.md) · [00 全程走读](00_一条记录从原始Task到训练.md) · [01](01_数据理解与GT构建.md) · [02](02_Verifier与任务池验收.md) · [03](03_Rollout与GRPO机制.md) · [04](04_真实训练与独立评测.md) · [反向补充源码](examples/source-supplements/README.md) · [训练准备](examples/training/README.md)

**这一篇解决什么：** 本机没有 GPU，训练跑不了（见 [CLAUDE.md 第 3 节](../CLAUDE.md) 的环境现状）。那么只学不复现，能不能把 RLVR 学到能过面试的程度？还要补什么？本文分「仅学习」和「实跑」两条路线，分别写清要补什么、能学到什么、面试能答到哪。它是一份持续维护的文档：结论随学习进度和你的回答更新，改动记在文末。

**一句话结论（按你 2026-10-15 的回答定）：** 可行。你的目标是业务算法岗，做后训练和后训练数据构造；RL 和 LLM 训练都有基础；实跑预算 300 元以内；面试在两到三个月后。数据构造正好是这套资料加补强项最强的部分；机制、设计、取舍和源码证据这一层，仅学习就能答到位。「你训练时看到了什么」这一层，仅学习只能靠作者公开日志和文献来答，要坦白说没跑过。推荐路线：仅学习全程做完，加一次单卡 smoke（几十到两百元，必做），剩余预算视每步耗时决定做不做缩水版小规模训练。

## 一、可行性判断

**仅学习能过面试的前提有三条：**

1. **把作业做完，不是只读。** 面试里最值钱的不是背下 -1.1/0.1/1.1，而是能说「我在 LeetCode 53 上自己加了一条全负输入，看着 wrong_empty 从 1.1 掉到 0.1」。作业产出的 attempt、notes 就是你的证据。目前 01 的作业还没开始做。
2. **补上 Code-R1 没覆盖的面试面。** 这套资料围绕一个仓库讲一条流水线，而面试会横向问：PPO 和 GRPO 的差别、DAPO 和 Dr.GRPO 改了什么、KL 三种估计、训练曲线怎么看、Ray 和 vLLM 怎么配合。这些是资料要补的，清单见第三节。
3. **用对话术。** 不夸大，不回避：「我在 Code-R1 源码上把 reward 路径在 CPU 上完整复现并验证过，发现并修了几处判分缺口；GPU 训练我（没有做过 / 只做过一次单卡 smoke），训练动态是从作者公开日志和论文里学的。」面试官追问训练细节时，用机制推断加文献回答，并说明这是推断。

**仅学习在什么情况下不够：** 岗位的核心职责就是大规模后训练，面试官会连续追问调参和故障处理的亲历细节。这种岗位，同场竞争者多半有真实训练经历，仅学习是明显短板；单卡 smoke 能补一部分，小规模训练才能补到「我观察过 reward 曲线和长度增长」这一层。

**你手里已经有的面试资产（都是真的、可复现的）：**

- 121 道树和链表题因为 GT 不拼运行前缀而必然失败，正确解只拿 0.1；补强版修好后全部恢复（[01 内部审查](01_数据理解与GT构建.md#internal-external-review)）。
- `sys.exit(0)` 提前退出拿满分，换沙箱堵不住；受保护判题协议怎么设计（[02 执行边界](02_Verifier与任务池验收.md#execution-gaps-2)）。
- 判题故障记 0.0 会让同组三条错误回答拿到 +0.5 的 advantage；整组作废怎么做（[补强项 6](examples/source-supplements/README.md)）。
- LeetCode 测试全是题面样例，中位数 2 条；变异审计 2014 题、17316 个变异体、杀死 81%，但杀死率高不等于够（[补强项 2、3](examples/source-supplements/README.md)）。
- 训练脚本的几处运行态事实：mini-batch 单位错配让梯度缩到 1/16、第一步 lr=0、单 mini-batch 时 PPO clip 不起作用、单卡配 vLLM 0.7.3 第一次生成就失败（[CLAUDE.md 第 7 节](../CLAUDE.md)，源码推断，未实跑）。

这些是「读源码读出来、CPU 上验证过」的发现，比复述论文更有说服力。

**对你的岗位（业务算法，后训练与后训练数据构造）：** 面试的重心会落在「怎么构造可验证的任务和测试、怎么保证 reward 可信、怎么选题和去污染、SFT 数据和 RL 数据怎么配合」，其次才是训练循环本身。前者是 01、02 加补强项的全部内容，已经有实测数字；后者有 03、04 的机制主线。真正要补的是横向视角：不同数据来源怎么接、LLM 生成测试怎么核、冷启动 SFT 与 RL 的分工、难度课程。见第三节第 9 项。

## 二、两条路线一页对比

| | 仅学习 | 实跑一档：单卡 smoke | 实跑二档：小规模训练 | 实跑三档：完整复现 |
|---|---|---|---|---|
| 要什么 | 本机 Mac，子模块已初始化；可选一个仓库外 venv 做 torch 验算 | 云上 1 张 24 GB 以上的 Ampere 或更新的卡，1–3 小时 | 1–2 张 80 GB 或 4 张 24 GB 卡，数小时到一天 | 8 张 80 GB 以上的卡（作者用 8×H200），一到两天 |
| 要补什么 | 作业做完；资料补 RL 基础、算法家族、训练动态、训练系统、手写题、问题库 | 仅学习的全部，加 Linux 环境、vLLM 0.6.3、flash-attn、firejail、模型下载、parquet | 一档全部，加评测协议、多 seed、难度筛选的真实通过率 | 二档全部，加吞吐与显存调优、12k 数据（TACO 要联网下载并用 firejail 验证） |
| 能学到什么 | 全流程机制、源码证据、判分与数据的真实缺口、公式与手写实现 | 真实采样产物、一步训练的日志、checkpoint 与恢复、权重同步、本机验证不了的 §7 事实 | reward、KL、熵、长度的曲线；训练前后 pass@k 的配对比较；当前 policy 的难度分布 | 论文级结果；OOM、长序列、吞吐瓶颈的亲历；完整效果实验 |
| 面试能答到哪 | 机制、设计、取舍、缺口：强。训练动态与调参：靠文献和作者日志，要坦白 | 多了「我跑过一步，日志里看到 ……」；调参仍是推断 | 能讲自己的曲线和调参过程；效果结论有小样本证据 | 能讲完整复现与调优经历 |
| 成本（估算） | 时间：每天 2–3 小时，2–3 周 | 云 GPU 几十到两百元 | 几百元 | 数千元起，取决于步数和卡型 |
| 适合谁 | 所有人的起点；RLVR 只是面试考点之一的岗位到此够用 | 后训练相关岗位的最低配置 | 后训练是核心职责的岗位 | 想拿「复现了 Code-R1」当作品的人 |

云 GPU 价格以平台当日报价为准：国内常见 AutoDL、阿里云 PAI，海外 RunPod、Lambda；消费级 4090 每小时约两三元，A100 80 GB 约五到八元，H100 级约十到二十元（2026-10 估算）。卡型要求来自 flash-attn 2：Ampere（A10、A100）、Ada（4090、L4）、Hopper（H100、H800、H200）可以，T4 和 V100 不行。

### 3.3 环境：可选但推荐一个仓库外的 venv

作业本身只要标准库。但第 5 项手写题要对照 `core_algos.py` 验算，奖励管理器的端到端演示要 torch，所以建议建一个仓库外的 venv，命令和已验证的版本见[反向补充源码的「怎样运行」](examples/source-supplements/README.md)。venv 不能建在仓库里：补强版沙箱禁止读仓库，解释器在仓库里会启动不了。

### 3.4 仅学习能学到什么、学不到什么

能学到：

- 一条记录从原始题到参数更新的全部机制，每一步有源码定位和 CPU 实测数字。
- 数据、测试、判分、沙箱的真实缺口和修法，以及工业界的对应做法。
- GRPO 的 advantage、ratio、clip、KL、mask、loss 聚合，能手算、能手写。
- 训练脚本的运行态事实（mini-batch 错配、lr=0、clip 失效），从源码推出来，知道去哪里核实。
- 评测协议：pass@k、贪心与采样、baseline 配对、去污染。

学不到：

- 真实采样的分布：多少回答格式失败、多少组全同、回答有多长。
- 训练曲线和调参手感：KL 系数、学习率、batch 怎么影响曲线，什么时候该停。
- 运维经历：OOM、吞吐、权重同步出错、firejail 并发问题。
- 效果结论：训练前后 pass@k 的真实差异。

## 四、实跑路线：三档

| | 一档：单卡 smoke | 二档：小规模训练 | 三档：完整复现 |
|---|---|---|---|
| 做什么 | 跑[训练准备里的 learn_smoke](examples/training/README.md#batch-contract)：0.5B 模型、4 题 × 4 回答、1 步，再按恢复命令续 1 步 | 1.5B 或 3B 模型，LeetCode 2k 训练集，几百步，每 16 步贪心验证 | 作者配置：7B、12k 数据、832 步，或 2k 数据、1088 步 |
| 硬件 | 1 张 24 GB 以上的卡；24 GB 卡要把 vLLM 显存比例调低并开梯度检查点（估算，未实测），稳妥是 A100 80 GB | 1–2 张 80 GB，或 4 张 24 GB 配 TP=2 | 8 张 80 GB 以上 |
| 软件 | Linux、CUDA 12、torch 2.4.0、vLLM 0.6.3（单卡不能用 0.7.3）、flash-attn、ray、firejail；模型先下载到本地 | 同一档 | 同一档，再加 TACO 数据的下载与 firejail 验证 |
| 前置检查 | [训练准备的「实跑前必查」](examples/training/README.md#batch-contract)五条；先跑仓库自带的 tiny Llama 冒烟确认 verl 能起；再做 firejail 探针确认分数不全是 0 | 同左，加评测协议预登记：固定题集、seed 列表、重复次数 | 同左，加吞吐与显存预算 |
| 多学到什么 | 真实采样的 16 条回答长什么样；一步训练的 reward、KL、grad_norm、lr；checkpoint 目录与恢复；权重同步时序；亲眼看到第一步 lr=0、clipfrac=0 | 曲线怎么走、什么时候该停；难度筛选用真实通过率（补强项 7 的输入）；训练前后 pass@k 的配对比较与 seed 波动 | OOM 与长序列处理、吞吐瓶颈、多卡 TP 与 FSDP 的配合；论文级数字 |
| 面试增益 | 「我跑过一步」加几条亲历观察；训练动态仍主要靠文献 | 能讲自己的曲线、调参和效果证据 | 能讲完整复现和调优 |
| 成本（估算） | 几十到两百元，含装环境的时间 | 几百元 | 数千元起 |

**按 300 元预算怎么用：** 一档必做，预计几十到两百元。二档只能做缩水版：0.5B 或 1.5B 模型、LeetCode 训练集、一两百步、单卡，预算封顶。做法是先在一档里测出每步耗时和显存，再按剩余预算反推步数；步数太少看不出曲线就不做，把钱留给重跑一档。三档不做。

实跑不改变学习内容，只是把「推断」换成「观察」。所以无论哪一档，都先走完仅学习路线，再上 GPU。

上 GPU 之前，先用 [05 实跑推演](05_实跑推演_Qwen3-8B.md) 把七个环节的决定练一遍：它按真实运行的产物形态做了一次 Qwen3-8B-Base（预训练模型，没经过 SFT 或 RL，R1-Zero 式起点）的两轮 GRPO，费用、显存、曲线、事故、评测、归因都有数，但明确标注是推演。

## 六、诚实话术

**三十秒版：** 「我以 Code-R1 为教材，把代码 RLVR 的闭环从原始题到参数更新逐站拆开，在 CPU 上用固定候选复现并验证了判分和 advantage 路径。过程中发现原版几处缺口：121 道树和链表题因为 GT 不拼运行前缀必然判错、提前退出能骗过判分器、判题故障记 0 会污染组内 advantage、测试只有题面样例不足以抓错解。我在原版旁边实现了一套补强模块：受保护的判题协议、结构化沙箱、故障整组作废、变异审计和补测试，都在 CPU 上验证过。GPU 训练我（没有做过 / 做过一次单卡 smoke），训练动态是从作者公开日志和论文学的。」

**被问「你训练过吗」：** 不绕。「没有做过多卡训练。我做到的是：读通了训练主线的源码并推出几处运行态事实，比如这份脚本的 mini-batch 单位错配会让梯度缩到 1/16、第一步 lr 是 0、单 mini-batch 时 PPO clip 实际不起作用；（如果做了一档）我在单卡上跑过一步并验证了其中两条。」然后把话题引回自己有证据的部分。

**被问训练曲线：** 「我看的是作者公开的 wandb 日志和论文里的曲线：reward 和回答长度一起涨、KL 缓慢上升、熵下降……这些是观察别人的，不是我调的。」说明来源，比编一个「我当时调到 0.001」可靠。
