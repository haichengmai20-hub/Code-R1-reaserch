## D1 题面与 prompt：三条边界

**结论：** 描述给全、约束该给、样例永不给。
- **描述给全**：`meta.query` 与 `meta.question_title` 的第一段描述**一字不差**；「完整题面」多出来的是 Examples、Constraints、Follow-up，不是描述。
- **约束该给**：数值约束是语义消歧的真信息（元素可全负 + 非空约定 → `wrong_empty` 的「空子数组」解读被判错）；复杂度约束是采样提示，不是训练信号（见 D5）。
- **样例永不给**：LeetCode 的 `test` 就是题面样例（1890 题断言数 = 样例数）；给样例 = 把判分依据明文递给模型，照抄三条输入输出即可白拿 1.1，破坏「可验证奖励」前提。
- **原版为什么只取 query**：判分器不读题面，只认签名和测试；`query`（描述+签名）是「能进判分器的最小充分输入」，取它是代码数据集惯例的继承。代价：语义歧义 + 121 题 prelude 缺失。

**依据：** 2026-11-07/08 讨论；`raw_task.json` 实测两字段对齐；`report.json` 的 wrong_empty 证据。

**代码位置：** `examples/data_preprocess/coder1.py:326`（原版只取 `meta.query`）；`RLVR学习资料/examples/maximum-subarray/run_demo.py:37-41`（demo 的 `ACTOR_PROMPT_APPEND` 补约束）；**`coder1_plus.py --append_constraints`（2026-11-08 补：正式管线自动解析 Constraints 并规范化追加，上标 `105`→`100000` 同规则修复；实测 1890 题成功 1846 题，解析不出的保持原样不硬造；默认关闭以保持与原版逐字相同的单变量对照）**。

## D4 性能轮设计（补强项 10）

**结论：**
- **离线一次性标定**：约束解析定规模上界（`105`→10⁵、`10**5`、`5*104` 三种写法）→ 按上界造大输入（封顶 100,000、下限 1,000）→ 参考解实测墙钟（取两次较慢者）×3 = `time_limit_ms`（下限 500ms）。训练时零标定开销，同题各 step 标准不漂移。
- **判分侧两轮**：正确性轮通过且有 `extra_info.perf` → 性能轮（种子确定性重建大输入，`sandbox.run_python(timeout=time_limit_ms/1000)`）。错答不触发。
- **状态（2026-11-09 归因修正，随测试扩容方案 D13 落地）**：超时 = 性能瑕疵；**大输入输出不符/出错 = 正确性失败（0.1 档）**——大输入是题意合法输入，答错就是错解；留在 0.9 会让崩溃的错答与慢而对打平，破坏「任何对答严格高于任何错答」。`infra_error` 走补强项 6 处置（2026-11-09 起为 D15 单条掩码）。
- **legacy**：`CODER1_PLUS_REWARD=legacy` 整体跳过（推演口径不变）。
- **计时噪声缓解**：3× 系数、500ms 下限、两次实测取慢、infra 故障按 D15 处置。
- **数据链路**：`coder1_plus_perf.py` 产出 `perf-index.jsonl` → `coder1_plus.py --perf_index` 并进 `extra_info.perf`。

**依据：** `perf.py`；`coder1_plus_perf.py`；`coder1_plus.py --perf_index`（2026-11-08 补）；`verify_perf_round.py` 18/18（2026-11-09 增「大输入答错 → 0.1」对照）；Polygon/CodeContests 先例。

## D5 复杂度约束的定位

**结论：** 复杂度约束（`len ≤ 10^5`）是 **prompt 提示**，不是训练信号——RL reward 只测输出，O(n²) 对与 O(n) 对同分、advantage 相同。它要变成信号必须显式接进 verifier（D4）。复杂度真正的兑现发生在评测（大输入 + 紧 timeout），不在训练数据里造大数组。

**依据：** 源码（reward 只读退出码）；2026-11-07 讨论结论。

## D12 参考解不可得 → 过滤（宁缺毋滥，2026-11-09 用户定案）

**结论：** 构造训练数据时，**参考解拿不到的题在过滤关整题丢弃**。不用 LLM 兜底生成参考解（宁缺毋滥）。丢弃不静默：记录清单与原因（slug、缺在哪一环：无社区解/无文件夹）。

- **理由：** 参考解拿不到 → 三角自洽（题面↔样例↔参考解）无从做起 → 行为层验收缺一角，GT 可信度只剩格式层。与 TACO「`solutions[-1]` 跑不通测试就删题」同构——把「跑不通验收的题不要」前移一格到「没有参考解就无从验收」。
- **获取途径按可信度：** 社区题解库（doocs，2026-11-09 实测：1890 题训练池的 1868 道算法题文件夹级覆盖 1868/1868；README 含 Python3 解抽样 32/40≈80%；另 22 道为面试金典 `lcci` 题）＞ 竞赛平台提交 ＞ LLM 生成（不启用）。
- **代价要计量：** 丢弃不是随机的（doocs 缺 Python 解的多为新题/冷门题），过滤前后对比难度分布，丢弃清单随数据版本发布。

**依据：** 2026-11-09 讨论；`reference_probe.py` 实测（4 题 6 解全过行为层验收；3/4 题「方法一」与冻结 completion 相似度 ≥0.99，出处即 doocs）。

**代码位置：** 补强项 11（2026-11-09 落地）：`examples/data_preprocess/coder1_plus_reference.py`——`coverage` 子命令产出 `drop_reference_missing.json`（JSON list，直接给 `coder1_plus.py --drop_task_ids`，即补强项 7 的机制）与难度分布对照；`fetch` 子命令取参考解并做行为层验收。学习侧探针 `RLVR学习资料/examples/upstream_probe/reference_probe.py`。单元测试 4 条进 `test_source_supplements.py`（27/27）。

## D14 入池质量门：参考解可用性与测试覆盖度接入过滤（2026-11-09 用户定案）

**结论：** 过滤关的判据从 D12 的单条扩成**四道质量门**，全部「记原因、不静默」：

| 门 | 判据 | 不过的处理 | 实现 |

| ③ 覆盖度（补强前） | 现有样例的覆盖测量——**不是丢弃理由**，是扩容优先级与对照基线 | 记录进报告 | ⏳ 接测试扩容方案（D13）阶段 A/B 的覆盖清单与指标 |

## D15 判题故障的终处置：单条掩码（2026-11-09 用户定案，取代 D6 时期的整组作废为默认）

**结论：** 判题故障重试仍失败后，默认**单条掩码**（`mask_sample`）：故障样本的分数设为**组内有效样本的均值**——GRPO 组内标准化后它的 advantage **恰为 0**（零梯度、不替未知质量做任何主张），其余已判分的 rollout 照常提供相对信号，**不为一条故障浪费整组采样**（用户原话：不想浪费已经跑的其他 rollout）。数学：注入有效均值 m 后组均值仍为 m，故障样本离差为 0；有效样本离差不变、组内尺度被均匀放大 sqrt((n−1)/(n−2))（方向与组内排序不变）。**组内全部故障时退回整组作废**（无有效样本可参照）。`neutralize_group`（整组作废）降为可选项——保守场景（故障批次相关、连坐邻居）仍可选；`legacy_zero` 复现原版。

- 为什么占位值调不出更好的（对拍）：0.0 → 错答被奖励（BC-10）；0.2（略高于错答）→ 占位样本拿全组最强正信号 +1.5（组内 std 只有 0.05，绝对差距活不过标准化）；0.1 →「未知」被主张成「等于错」。任何具体数值都在替未知质量伪造主张，掩码（advantage 恰 0）才是「不知道」的正确表达。
- 已知性质：故障样本的 token 仍占 loss 分母（masked_mean 的分母，与整组作废同性质）；日志里故障样本显示的分数是掩码注入值（=组内有效均值），不是质量评价。
- 开关：`CODER1_PLUS_INFRA_POLICY=mask_sample|neutralize_group|legacy_zero`（默认 mask_sample）；单条掩码 vs 整组作废的权衡在故障的相关性——单点独立故障掩码更省，批次相关故障作废更稳。

**依据：** 2026-11-09 讨论（用户提出不浪费已跑 rollout）；`[0.1,0.1,0.1,0.2]→[−0.5×3,+1.5]` 的对照计算；单元测试 31/31（掩码恰零、全同组无信号、全故障退作废、旧策略可选）；`verify_reward_manager_cpu.py` macOS CPU 全过（无 firejail 场景：格式门先记 −1.1 的真分数 + 3 条故障被掩码 → 全组同分 advantage 全 0）。

**代码位置：** `verl/workers/reward_manager/infra_policy.py`（`mask_sample` 默认 + 数学注释）、`prime_plus.py`（环境变量开关、docstring）。

## D16 傻解法 oracle：每题的唯一指向标（2026-11-10 用户定案）

**结论：** 环境排障（BC-24 铁律）之外，**每道题标配一个「傻解法」独立 oracle**——暴力或枚举，写法故意蠢到「显然对」（按题意直译、零优化），作为 expected 的**唯一指向标**。答案争议一律由它终审：参考解、doocs 社区解、LLM 输出、生成器的 expected 全是**被审对象**，不再对等仲裁（旧口径的三方 2v1 降级为辅助证据与参考解候选池）。

- **锚点背书（一次性，标准最高）**：超小域穷举对照 + 人工审读（蠢到显然对）+ 跑通全部旧 seed。锚点是唯一没有更高级仲裁者的组件，只能靠题意层面的硬证据背书。
- **锚点失稳最高优先级**：oracle 自己崩了或可疑 → 穷举校准 → 修 oracle → 它判过的样例**全部连坐重审**。
- **大输入域**（傻解法跑不动，如 O(n²) 对 n=10⁵）：指向标换成「**经 oracle 验收过的高效参考解**」——信任由傻解法传递（D13 §5 的分层：小输入暴力终审，大输入交叉验证的高效实现）。
- **仲裁产出**：参考解错 → 该样例是高价值测试（expected 用 oracle 的，收）+ 参考解换 doocs 方法二重新过 oracle 验收，无解可换整题丢（D14 门②）；expected 来源错 → 修正 + 同批复查；oracle 与参考解一致而判分失败 → GT 层比较器问题（如 any-order）。

**依据：** 用户 2026-11-10 定案（原话：「每道题都能配一个完全对的傻解法：暴力或者枚举当作唯一指向标」）；LC53 先例——O(n²) 全子数组枚举对拍 Kadane，定向补全负 `[-3,-2,-5]→-2` 抓住 wrong_empty。

## D17 扩容工作流敲定：边界的三层来源 + 只造输入（2026-11-10 用户定案）

**结论：**
1. **每题需要补什么边界，三层分工（2026-11-10 修订：语义层验收去人化）**：数值边界由程序从 Constraints 机械推导（长度/值域上下界、单元素、零值——零成本可复用）；语义边界与 validate 校验器由 **LLM 读题面起草**（LLM 是草稿员，永不碰最终答案），其验收**不用人审、用双向对拍自动完成**——①不误杀：全部旧 seed + oracle 小域生成的合法流必须全过；②不漏放：约束越界输入（程序造）与**语义破坏变异**（把有序数组换两元素、树加一条边成环——变异器是机械的）必须全拒。漏登记的边界由**错解反推**自动发现（存活错解的区分输入即漏掉的边界）。**空输入是题意相关边界的典型成员**：是否合法由每题 validate 按语义裁决（LC53 不允许空数组即拒；语义允许空的题必须造——空输入是模型高频错点），不在生成器硬编码。人工只剩两处且均可抽样：审覆盖清单的分母（题意理解层）与背书锚点 oracle（一题一次，穷举对照本身是机械的）。
2. **只造输入，expected 唯一出自 oracle**：生成器只产出输入（generate → validate 含语义校验）；expected 一律 `oracle(input)` 现算，手算与 LLM 拍数不进管线。输入合法的前提下，冲突一律归参考解（D16 终审），归因树中「expected 来源错」分支删除，唯一例外为锚点失稳。
- **大输入域**：oracle 跑不动，expected 由「经 oracle 验收的高效参考解」产出（信任链传递，D13 §5）。
- **多解/构造型输出**：oracle 只产出「一个合法样本」，判分用合法性判定器（`compare=unordered_outer` / validator），不比具体值。

**依据：** 用户 2026-11-10 敲定（原话：「只有造输入，输出直接用 oracle 造」「边界数据还要满足语义条件」）；`coder1_plus_oracles.py` 的 generate/validate/oracle 三件套即此结构；LC53 的全负边界由错解反推（wrong_empty 存活）发现的先例。

## D18 参考解的最终定位（2026-11-10 用户定案，v3）

**结论：** 在本项目配置（GT＝样例＋小输入边界补充；perf 轮可选）下，参考解三个角色：

1. **错解池母体（核心，无条件）**——错误分布匹配：池子要模拟「考生会犯的错」（聪明解的初始化/边界/策略失误），变异参考解是最廉价可复现的来源；变异 oracle 的傻错误分布与模型不相交，检出率是假安全感。池子三源合流（变异/LLM 写 subtly-bug/模型真实输出）。
2. **性能指标构建的必需件（开 perf 轮时）**——`time_limit_ms`＝参考解墙钟 ×3、大输入 expected＝参考解输出；oracle 不可顶替：标尺必须量「正确且高效」的耗时，傻解法对大输入跑不完，其墙钟无标定意义。
3. **探针（保留）**——性能维度唯一可用：oracle 会被时限拦住，超时的探针分不清「环境坏」还是「自己慢」，失去探针定义（已知正确＋预算内跑完）；形态敏感问题（BC-24 类）参考解更锐利。oracle 任小输入正确性链路的基础探针。

已撤回的表述：「大输入 expected 打印机」作为无条件角色——GT 小输入配置下不存在，仅作为角色 2 的一部分随 perf 轮出现。

**依据：** 用户 2026-11-10 两轮澄清（项目样例不多；探针须考虑 oracle 被沙箱时限拦住）；BC-24（形态敏感探针先例）；补强项 10 标定链。

**md 位置：** 本条为口径定案（暂不改正文；01 若日后写参考解定位一节，以本条为准）。

## D19 冒烟门控晋升协议：审计闭环放进 smoke，达标才上正式训练（2026-11-10 用户定案）

**结论：** 把「escaped 错解检测 → 反馈修测试」的闭环放在**冒烟测试**里跑，用真实 rollout 产生真实错误分布；失败率降到**预注册阈值**以下才晋升正式训练。分五步：

1. **预注册判据（开跑前写死，不许事后调）**：两个率 + 样本量 + 决策规则。
   - **escaped 率**＝满分回答在 held-out 审计输入上的失败比例（held-out 输入不参与该轮 smoke 判分）；
   - **误杀率**＝正确解被拒比例，**必须为 0**；
   - 样本量决定可承诺的置信度（rule of three：0 漏判在 N 个样本上的 95% 上界 ≈ 3/N）——N=20→≤14%、N=60→≤5%、N=300→≤1%。冒烟按可承受样本设粗阈值（如 N=60、escaped≤5%、误杀 0），要 <1% 的硬上界只能靠正式训练期审计补足。
2. **跑 smoke**：固定起点、7 道试点（oracle 已有）+ 小池，单卡短跑，收集真实 rollout。
3. **审计**：满分回答用 held-out 输入重赛 / 对拍 oracle → 统计两率。
4. **反馈五条路**：回归（露馅输入进 GT）→ 定向扩容（同类输入批量补）→ 清单修正（系统性盲区修分母）→ 训练决策（held-out 不涨就停训查数据）→ 不动（低于阈值不动作）。修完重跑 smoke，循环。
5. **晋升**：达标 → 测试集冻结 `test_version` 作为正式训练 GT；**审计不停止**——正式训练期间与之后继续抽满分回答在新输入上复审（D13 阶段 D），因为模型变强会产生新错法，smoke 达标是准入的最低证据、不是终身保证。

**训练配置（2026-11-10 查实）：** 原版 `main_grpo.sh` `ROLLOUT_N_SAMPLE=16`（16 题×16＝256 条/步）；用户推演方案 n=8（6144/200 步）；冒烟建议 n=8~16，base 弱时 n=16 更易出现混合组、配合按通过率筛题。

**样本量规则（预注册，精确二项上界）：** N=60 且 0 漏判 → 95% 上界 4.9%（可停）；N=100 且 ≤1 漏判 → 4.7%；N=100 且 2 漏判 → 6.2%（不通过）。满分样本跨 step 累计、按题分层（同题 16 条相关，有效样本 < N）；提前停必须卡 N=60，30 个 0 漏判的上界 ≈9.5% 不够。

**强模型与 base 的分工（同时进行、顺序固定）：** 测试质量是策略无关的、escaped 率是策略相关的——①调 GT/verifier 用**强模型离线对抗审计**（产量高、错误形态接近聪明解；测试必须在至少与未来正式模型一样强的对手面前审；误杀率用 oracle 查、零模型成本）；②阈值/准入与训练健康用 **base 冒烟**（escaped 率是该策略的真实风险；base 满分少→跨步累计，N 不够就如实报证据弱，不降低阈值凑达标）；时序：冒烟前强模型审计冻结 v1 → 冒烟中审计→v2 → 达标晋升 → 正式训练期继续抽检。

**已注册的边界：** 冒烟模型 ≠ 正式模型（单卡、短步数、不同采样），错误分布会漂移；预算内循环仍未达标 → 记录缺口并带风险标记进入（或缩小正式规模），不许无限循环也不许假装达标。

**依据：** 用户 2026-11-10 定案（「这部分可以在冒烟测试进行，把失败率降低之后低于阈值直接上正式训练」）；承重前提是测试可再生（D16/D17 造数管线），否则 held-out 无意义。
